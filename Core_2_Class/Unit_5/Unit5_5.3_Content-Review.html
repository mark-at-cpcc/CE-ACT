Part 1 — Windows Security Settings (Objective 2.2)

Defender Antivirus and the Firewall

Defender Antivirus can be activated or deactivated, and its definitions must be kept updated — signature-based detection only recognizes what it already knows. The firewall is likewise activated or deactivated, and configured for port security and application security, which is the application exception you met in Unit 3.

Users and Groups

Account or ConceptWhat It Means
Local vs. Microsoft accountAn account that exists only on this machine, versus one tied to a Microsoft identity that syncs settings across devices
Standard accountOrdinary use. Cannot make system-wide changes without elevation.
AdministratorFull control of the machine. The account malware most wants to be running as.
Guest userLimited temporary access. Disabled in nearly every real environment.
Power userA legacy group retained for backward compatibility; it no longer carries the elevated rights it once did

Sign-In Options

Username and password, PIN, fingerprint, facial recognition, SSO, and passwordless sign-in with Windows Hello. A PIN looks weaker than a password and is usually stronger in practice: it is tied to one device and backed by the hardware, so a stolen PIN is useless anywhere else.

NTFS and Share Permissions

NTFS permissions

Permissions stored on the filesystem itself. They apply whether the user reaches the file across the network or sits at the machine.

Share permissions

Permissions on the network share. They apply only to users arriving over the network, and not at all to someone signed in locally.

The Most Restrictive Wins

When a user reaches a folder across the network, Windows evaluates both sets and applies the more restrictive of the two. Share permissions say Full Control and NTFS says Read? The user gets Read.

This is why "I gave them Full Control and they still cannot save the file" is such a common ticket. The technician changed one set of permissions and never looked at the other. Check both, every time.

File and folder attributes and inheritance complete the picture: by default a new file inherits the permissions of the folder it is created in, which is what makes permissions manageable at all — and what surprises people when a file moves.

Elevation and Encryption

  • Run as administrator vs. standard user — elevate for the one task that needs it, then go back
  • User Account Control (UAC) — the prompt that appears before an elevated action. It exists so that elevation is a decision rather than a default.
  • BitLocker — full-volume encryption for a fixed drive
  • BitLocker To Go — the same protection for removable media
  • Encrypting File System (EFS) — encryption of individual files and folders rather than the whole volume

Active Directory

The domain you met in Unit 3, from the administrator's side. The objective names joining a domain, assigning a log-in script, moving objects within organizational units, assigning home folders, applying Group Policy, selecting security groups, and configuring folder redirection.

Connect It to Unit 3

In Unit 3 a domain was something a workstation joins. Here it is the machinery that makes least privilege practical at scale: you do not set permissions for four hundred people, you put them in security groups and set permissions once. The log-in script that maps everyone's S: drive is the same scripting use case you met in Section 3.3.

Part 2 — Wireless Security (Objective 2.3)

Protocol or MethodWhat to Know
WPA2The long-standing standard, using AES encryption. Still widespread.
WPA3The current standard. Choose it when every device supports it.
TKIPThe older encryption method paired with the original WPA. Deprecated; its presence is a finding, not a recommendation.
AESThe strong encryption standard used by WPA2 and WPA3
RADIUSCentralized authentication, so users sign in with their own credentials rather than a shared wireless key
TACACS+A similar centralized approach, commonly used for administrative access to network devices
KerberosTicket-based authentication, the mechanism behind Active Directory sign-in
MultifactorMore than one kind of proof, applied to wireless access as it is elsewhere
A Real Example You Will Meet on the Job

A small office uses one wireless password that everyone knows, and an employee leaves. Changing the key means reconfiguring every phone, laptop, printer, and thermostat in the building, so nobody changes it — and the former employee can still reach the network from the parking lot. RADIUS solves this: each person authenticates as themselves, and disabling one account ends that person's access without touching anyone else's device.

Part 3 — Mobile Device Security (Objective 2.8)

  • Hardening techniques — device encryption; screen locks using facial recognition, PIN codes, fingerprint, pattern, or swipe; and configuration profiles that apply a managed set of settings
  • Patch management — OS updates and application updates
  • Endpoint security software — antivirus, anti-malware, and content filtering
  • Locator applications — finding a lost device
  • Remote wipes — erasing a device that is not coming back
  • Remote backup applications — which is what makes a remote wipe survivable
  • Failed log-in attempt restrictions — the mobile equivalent of account lockout
  • Policies and procedures — MDM, BYOD versus corporate-owned devices, and profile security requirements

The Screen Lock Is Not the Security — Encryption Is

A screen lock stops someone picking up the phone and using it. It does nothing against someone who takes the storage apart. Device encryption is what makes the data unreadable, and on modern phones the screen lock credential is what unlocks the encryption key. The two work together, which is why a device with no lock set is often not encrypted in any meaningful way either.

For the exam: if the scenario is a lost or stolen device, the answer usually involves encryption, a locator application, or a remote wipe. If it is shoulder-level access, the answer is the screen lock.

Part 4 — Securing a SOHO Network (Objective 2.10)

Router Settings

SettingWhy It Matters
Change default passwordsDefault credentials for every consumer router are published online. This is the first step, every time.
IP filteringPermits or blocks traffic by address
Firmware updatesRouters are computers, and unpatched routers are a standing vulnerability
Content filteringBlocks categories of sites, often required in schools and public spaces
Physical placement and secure locationsA router in an open lobby can be reset to factory defaults by anyone holding a paperclip
Universal Plug and Play (UPnP)Lets applications open ports by themselves. Convenient, and a common finding — usually disabled on a business network.
Screened subnetA separate segment for systems that must be reachable from outside, kept away from the internal network
Configure secure management accessAdminister the router over an encrypted connection, from inside the network only

Wireless-Specific Settings

  • Changing the SSID — a default network name tells an attacker the make and model of the router
  • Disabling SSID broadcast — hides the name from casual scanning. Know it for the exam, and know that it is weak protection: the network is still visible to anyone with the right tool.
  • Encryption settings — WPA3 where supported, WPA2 with AES otherwise
  • Configuring guest access — visitors get internet without reaching the internal network

Firewall Settings

Disabling unused ports closes doors nobody is using. Port forwarding and mapping deliberately opens one, directing outside traffic to a specific internal device — necessary sometimes, and a risk to be justified each time.

The First Five Minutes With Any New Router
  • Change the administrator password before the device is connected to the internet
  • Update the firmware
  • Set the SSID to something that does not identify the hardware or the owner
  • Set encryption to WPA3, or WPA2 with AES
  • Disable UPnP unless something genuinely requires it
  • Restrict management access to the internal network

Six steps, five minutes, and it eliminates most of the ways a small network gets compromised.

Part 5 — Browser Security (Objective 2.11)

Getting the Browser Safely

Download from trusted sources, and where a publisher provides one, verify the download with hashing — comparing a computed value against the one the publisher published. Untrusted sources are how browsers arrive pre-loaded with things nobody asked for. Browser patching matters as much as operating system patching, because the browser is the program most exposed to hostile content.

Extensions, Plug-Ins, and Passwords

Extensions and plug-ins should come from trusted sources only. An extension can read every page you visit, which is precisely why a compromised one is so damaging. Browser feature management means being able to enable and disable plug-ins, extensions, and features deliberately. Password managers reappear here, and for the same reason as in Unit 4: they are the only practical route to unique passwords.

Connections and Certificates

Secure connections and sites with valid certificates are the browser's way of telling a user that a site is who it claims to be and that the traffic is encrypted. A certificate warning is not a formality to click through — it is the browser reporting that one of those two guarantees has failed.

Settings

SettingWhat It Does
Pop-up blockerSuppresses windows that open without the user asking
Clearing browsing data and clearing cacheRemoves history and stored page content — the fix for a surprising number of "this site is broken" tickets
Private-browsing modeKeeps no local history for the session. It does not make the user anonymous to the network or the site.
Sign-in and browser data synchronizationShares bookmarks, history, and saved passwords across devices — convenient, and worth a deliberate decision on a shared or corporate machine

Connect It to Unit 1

Section 1.B taught you to clear a browser cache so course pages would load correctly. Here you learn why that setting exists and what else it touches — a small housekeeping step in Unit 1 turns out to be part of an exam objective five units later. That is how this course is built.

Part 6 — Change Management (Objective 4.2)

In Plain Terms

Change management is the paperwork that stands between a good idea and an outage. It exists because most serious incidents are not attacks — they are changes that someone made on a Friday afternoon without telling anyone.

Documented Business Processes

  • Rollback plan — how the change is undone if it fails. Written before the change, not during the outage.
  • Backup plan — what is captured beforehand so that rollback is possible
  • Sandbox testing — trying the change somewhere it cannot hurt anyone
  • Responsible staff members — who does the work, and who answers for it

The Change Process

ElementWhat It Captures
Request formsThe formal record that a change was proposed
Purpose of the changeWhy it is being made
Scope of the changeWhat it touches, and what it does not
Change typeStandard — routine and pre-approved. Normal — requires review and approval. Emergency — made quickly under pressure, documented immediately afterward.
Date and time of changeIncluding change freezes, when no changes are permitted, and maintenance windows, when they are
Affected systems and impactWho and what will notice
Risk analysis and risk levelWhat could go wrong and how badly
Change board approvalsThe group that authorizes the change
ImplementationCarrying it out as approved
Peer reviewAnother technician checking the plan or the work
End-user acceptanceConfirmation from the people who use the system that it actually works

Emergency Change Is Not "Skip the Paperwork"

An emergency change — patching a flaw being actively exploited, for instance — is made quickly because waiting is the greater risk. The documentation still happens; it happens afterward.

On the exam and on the job, the distinction is timing, not existence. A technician who says "it was an emergency, so I did not document it" has described a process failure, not an emergency.

Part 7 — Backup and Recovery (Objective 4.3)

Backup Types

TypeWhat It CopiesTrade-Off
FullEverything, every timeSlowest to take, simplest and fastest to restore
IncrementalEverything changed since the last backup of any kindFastest to take, slowest to restore — you need the full plus every increment since
DifferentialEverything changed since the last full backupGrows each day, but restores from just two pieces: the full plus the latest differential
Synthetic fullA full backup assembled from an existing full plus its increments, without re-reading the sourceGives you the restore simplicity of a full without the time cost of taking one

Recovery, Testing, and Rotation

Recovery is either in-place or overwrite, restoring over the original, or to an alternative location, which is how you recover a single file without disturbing anything else.

Backup testing and its frequency is the objective people skip. A backup that has never been restored is an assumption.

  • Onsite vs. offsite — onsite restores fast; offsite survives the fire
  • Grandfather-father-son (GFS) — a rotation keeping daily, weekly, and monthly copies, so you can go back a day or a quarter
  • 3-2-1 backup rule — three copies of the data, on two different kinds of media, with one offsite
Backups Are the Answer to Unit 4's Worst Scenario

Ransomware is the reason 3-2-1 exists. An organization with current, tested, offline backups has an unpleasant day. An organization without them has a decision about whether to pay criminals. The difference is not skill or budget — it is whether someone tested a restore before they needed one.

Unit 5 Content Recap

  • NTFS permissions apply everywhere; share permissions apply over the network — and the most restrictive of the two wins
  • UAC exists so that elevation is a decision; BitLocker, BitLocker To Go, and EFS encrypt a volume, removable media, and individual files
  • Active Directory is what makes least privilege workable at scale: groups, policy, and log-in scripts
  • WPA3 where supported, WPA2 with AES otherwise; RADIUS replaces a shared key with individual accounts
  • On mobile devices, the screen lock stops a person and encryption stops a thief
  • Six settings secure almost any SOHO router, starting with the default password
  • A certificate warning is the browser reporting a failed guarantee, not a formality
  • Change management is the process that prevents self-inflicted outages; emergency changes are documented afterward, not skipped
  • Incremental is fast to take and slow to restore; differential is the reverse
  • 3-2-1: three copies, two media types, one offsite — and a restore you have actually tested
