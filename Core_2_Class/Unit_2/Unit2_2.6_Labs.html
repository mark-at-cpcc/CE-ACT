Every class opens with a Ticket of the Day. After that come two optional labs we run in class as time permits, and one take-home lab you do on your own machine. None of these is graded. All of them are where this week's reading turns into something you can actually do.

Ungraded Does Not Mean Optional Learning

The labs in this section carry no points. They carry something better: this unit is built almost entirely on "Given a scenario" objectives, and a scenario objective is a doing objective. Students who only read about Task Manager can describe it. Students who have opened it and sorted by CPU while something was actually wrong can use it — and that is what the exam and the job both ask for.

Name the Tool in Your Notes

This unit gives you tools to name, so your progress notes should start naming them. "Checked the computer" becomes "Opened Task Manager; a browser process was using 95% of the CPU. Ended the process; performance returned to normal." The second note tells the next technician what you saw and what you did.

Before You Touch Anything — Data Safety

This unit puts destructive commands in front of you for the first time. A mistyped command line does its damage instantly, with no confirmation and no undo.

  • Never run format, diskpart, rmdir /s, or robocopy /mir on a machine holding data you need
  • In diskpart, confirm the selected disk with list disk before any command that changes it — clean wipes whatever is selected
  • Open Registry Editor and look around as much as you like. Change nothing.
  • If you turn on Safe boot in msconfig, write "uncheck Safe boot" in your notes before you restart
  • Assume anything on a lab machine will be wiped — save nothing there

Lab 2.6.1 — MMC Scavenger Hunt

Wednesday · In class · 45 minutes · Objective 1.4

You will work in pairs. Every answer below lives in a different management console, so the real skill being practiced is choosing the right snap-in — which is exactly how the exam asks about them.

  1. Find the last unexpected shutdown. In Event Viewer, open the System log and locate the most recent Critical or Error entry. Record its date, its Event ID, and its source.
  2. Find a device with a problem. In Device Manager, look for any device showing a warning icon. If the machine is healthy, pick any device and record its driver version and driver date instead.
  3. Map the disk. In Disk Management, record how many physical disks the machine has, how each is divided, the file system and drive letter of each volume, and whether any unallocated space exists.
  4. Find something that runs by itself. In Task Scheduler, open the Task Scheduler Library and find one task that is not Microsoft's own. Record its name, its trigger, and what it runs.
  5. Check a service. In Task Manager's Services tab, find the print spooler. Record whether it is running and its process ID.
  6. Build your own console. Run mmc, then use File and Add/Remove Snap-in to put Event Viewer, Device Manager, and Disk Management into one window. Save it to the desktop. This is what technicians actually do.
Check Your Work

Trade answer sheets with another pair and name the snap-in each answer came from, without looking at your notes. If you can do that for all five, you are ready for the scenario questions on this objective.

Lab 2.6.2 — Command Line Relay

Thursday · In class · 45 minutes · Objective 1.5

Teams race through a sequence of commands. Speed is the hook; accuracy is the point. Every command here is read-only or works inside a practice folder you create yourself.

  1. Navigate. From wherever the prompt opens, use cd to reach the root of C:, then into your own user folder. Use dir to prove where you are.
  2. Reveal what is hidden. Run dir again with the switch that includes hidden files. Record one folder that appeared the second time and not the first.
  3. Build and fill. Create a folder called Relay with md, put two small text files in it, and list them.
  4. Copy it properly. Use robocopy with the switch that includes subfolders to copy Relay to a second location. Read the summary table it prints and record how many files it copied.
  5. Identify the machine. Run hostname, whoami, and winver. Record all three answers.
  6. Test the network. Run ipconfig and record the IP address, subnet mask, and default gateway. Then ping the default gateway and record whether replies came back.
  7. Look it up rather than memorize it. Run sfc /? and find the switch that scans and repairs system files. Do not run it — just find it and record what it does.
  8. Clean up. Remove both Relay folders with rmdir.
The Winning Team Is Not the Fastest

Teams are scored on correct recorded answers, not finishing order. A team that finishes last with eight right answers beats a team that finishes first with five. On the exam, the same trade applies.

Lab 2.6.3 — Take-Home: Your Machine, Your Tools

On your own · 1–1.5 hours · Ungraded · Objectives 1.4, 1.5, 1.6

In Unit 1 you inventoried your own machine. This week you operate it. Same computer, three new sets of tools — and by the end you will have a personal reference sheet you will still be using in Unit 6.

Nothing in this lab changes a setting. Every step is read-only: you are looking and recording, not configuring.

Part 1 — What Is This Machine Doing? (about 20 minutes)

  1. Open Task Manager with Ctrl+Shift+Esc. On the Processes tab, sort by CPU and record the top three processes and their percentages. Then sort by Memory and record the top three.
  2. Read the Performance tab. Record your total installed RAM, how much is in use right now, and your CPU's speed and core count.
  3. Check what starts itself. On the Startup tab, record how many programs are enabled and name the two with the highest startup impact.
  4. Run msinfo32 and record the BIOS mode, the system model, and the page-file location.
  5. Open Event Viewer and, in the System log, record the date and Event ID of the most recent Error or Critical entry. If there are none, say so — that is a finding too.

Part 2 — Eight Commands, One Machine (about 25 minutes)

Run each command and record its output in your own notes. Every one is safe and read-only. Check the Practice Safely box in Section 2.4 before you improvise.

  1. hostname — record the computer name
  2. whoami — record the account name, then run it again with the switch that lists group memberships
  3. winver — record the edition, version, and build
  4. ipconfig /all — record your IP address, subnet mask, default gateway, MAC address, and DNS servers
  5. ping your default gateway — record whether replies came back and the average time
  6. nslookup www.cpcc.edu — record the server that answered and the address it returned
  7. net use — record any mapped drives, or note that there are none
  8. gpresult /r — record whether any policies are applied to your machine

For each command, write one line in your own words saying what it told you. That line is what turns eight outputs into eight command cards.

Part 3 — Where Does It Live? (about 20 minutes)

Find each setting below in both Control Panel and the Settings app, and record the exact path to each. Some are easier in one than the other, and noticing which is part of the exercise.

  1. Show file extensions. Turn it on while you are there — it is the one change this lab recommends, and every technician should be running with extensions visible.
  2. Uninstall a program — find the list in both places. Do not uninstall anything.
  3. Set the default printer — find the setting in both places.
  4. Choose what closing the lid does (or, on a desktop, when the display turns off) — and record whether fast startup is on.
  5. Check for Windows updates — find it, and record the last date updates were installed.

Part 4 — Write It Up

One page, in the objective 4.1 ticket format: device information, what you were asked to determine, your progress notes, and a resolution. Your resolution should answer one question in plain language a customer would understand: based on what these tools showed you, is this machine healthy, and what would you check first if it slowed down tomorrow?

Bring It to Class

Bring your write-up and your command notes to Thursday's session. Your Part 2 notes are the reference sheet you will want in front of you during the Command Line Relay, and your Part 3 list is the beginning of the "where does it live" table that Section 2.4 asks you to keep.

What These Labs Give You

  • Practice choosing the right management console before you need it on a ticket
  • A saved custom MMC holding the three snap-ins you will open most often
  • Command-line fluency built on your own machine's real output, not on memorized syntax
  • A personal reference sheet of eight commands and what each one told you
  • A two-column map of where the same setting lives in Control Panel and in the Settings app
