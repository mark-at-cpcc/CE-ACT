All of them are where this week's reading turns into something you can actually do. Every class also opens with a Ticket of the Day — that section is at the end of this page.

Ungraded Does Not Mean Optional Learning

The labs in this section carry no points. They carry something better: this unit is built almost entirely on "Given a scenario" objectives, and a scenario objective is a doing objective. Students who only read about Task Manager can describe it. Students who have opened it and sorted by CPU while something was actually wrong can use it — and that is what the exam and the job both ask for.

Before You Touch Anything — Data Safety

This unit puts destructive commands in front of you for the first time. A mistyped command line does its damage instantly, with no confirmation and no undo.

  • Never run format, diskpart, rmdir /s, or robocopy /mir on a machine holding data you need
  • In diskpart, confirm the selected disk with list disk before any command that changes it — clean wipes whatever is selected
  • Open Registry Editor and look around as much as you like. Change nothing.
  • If you turn on Safe boot in msconfig, write "uncheck Safe boot" in your notes before you restart
  • Assume anything on a lab machine will be wiped — save nothing there

Event Viewer eventvwr.msc

Event Viewer is Windows' record of what happened and when. Services, drivers, applications, and Windows itself write entries to its logs. When a user says something happened "by itself," Event Viewer is where you find out what actually happened.

Anatomy of the Window

PartWhat You SeeWhat It Is For
Left pane: Custom ViewsSaved filters. The built-in Administrative Events view gathers Critical, Error, and Warning events from across the administrative logs.A fast first look at anything that went wrong
Left pane: Windows LogsApplication, Security, Setup, System, and Forwarded EventsThe five main logs. System and Application answer most help-desk questions.
Left pane: Applications and Services LogsDetailed logs for individual Windows components and installed programsDeeper digging once you know which component is involved
Center: event listColumns for Level, Date and Time, Source, Event ID, and Task CategoryScanning and sorting events. Click a column heading to sort.
Center: preview paneGeneral tab with the plain-language description; Details tab with the raw dataReading what a single event actually says
Right: Actions paneFilter Current Log, Find, Create Custom View, Save All Events As, Attach Task To This EventNarrowing, saving, and acting on events

Event levels: Information (something worked), Warning (something may become a problem), Error (something failed), and Critical (a serious failure, such as an unexpected restart). The Security log uses Audit Success and Audit Failure instead.

When a Technician Uses It

  • A computer restarted, crashed, or shut down without warning
  • An application keeps closing or will not start
  • A service, driver, or update failed
  • Someone needs to know who signed in, and when (the Security log)
  • Any ticket that needs evidence rather than a guess

How to Open It

  • Run: Windows key + R, type eventvwr.msc, press Enter
  • Quick Link menu: Windows key + X > Event Viewer
  • Computer Management: System Tools > Event Viewer
  • Windows Tools: Start > All apps > Windows Tools > Event Viewer

Most logs open for any user. The Security log requires administrator rights.

Primary Functions, Step by Step

A. Read a log.

  1. In the left pane, expand Windows Logs and select System.
  2. Click the Date and Time column heading to sort newest first.
  3. Select an event. Read the General tab in the preview pane: Log Name, Source, Event ID, Level, Logged, and the description.

B. Filter a log to just what matters.

  1. Right-click System and choose Filter Current Log.
  2. Use Logged to limit the time range, for example Last 24 hours.
  3. Check Critical and Error under Event level, or type specific IDs into the <All Event IDs> box, separated by commas.
  4. Click OK. When you are done, choose Clear Filter in the Actions pane.

C. Save a view you will use again.

  1. Right-click Custom Views and choose Create Custom View.
  2. Choose the levels and logs, give the view a name, and click OK. It now appears under Custom Views every time.

D. Save evidence for a ticket. With a filter applied, choose Save Filtered Log File As in the Actions pane. The resulting .evtx file can be attached to a ticket or sent to Tier 2.

Practical Example

The Ticket

"My computer restarted by itself overnight and I lost an unsaved spreadsheet. Did someone remote in?"

  1. Open the System log and choose Filter Current Log.
  2. Enter 41,1074,6008 in the Event IDs box and click OK.
  3. Read what you find. These three events, documented by Microsoft, tell planned restarts from unexpected ones:
    Event IDSourceWhat It Means
    1074User32A process or person started the restart, and the event names who or what and why — for example, Windows Update
    6008EventLogThe previous shutdown was unexpected
    41Kernel-PowerWindows restarted without shutting down cleanly: a crash, a power loss, or the power button held down
  4. Conclude. A 1074 naming Windows Update means a planned update restart, not an intruder. A 41 and a 6008 with no 1074 means an unexpected restart; the next question is power or a crash.
  5. Answer the user with what the log shows, and record the event IDs and times in the ticket.
Lab Task

On the lab computer: (1) Filter the System log for 41,1074,6008. Record the most recent event of each ID that appears, with its date, and state whether the last restart was planned or unexpected. (2) Clear the filter, filter for Critical and Error only, and record the most recent entry's Event ID, Source, and the first line of its description.

Cleanup: Clear Filter. Nothing else was changed.

Disk Management diskmgmt.msc

Disk Management shows every physical disk in the computer and how each one is divided into volumes. It is where a new drive becomes usable, where drive letters are assigned, and where volumes are resized.

Anatomy of the Window

PartWhat You SeeWhat It Is For
Top: volume listColumns for Volume, Layout, Type, File System, Status, Capacity, and Free SpaceA quick table of every volume and how full it is
Bottom: disk map, left blockOne block per physical disk: Disk 0, Disk 1, and so on, with type (Basic), size, and status (Online, Not Initialized, or Offline)Right-click here for disk-level actions such as Initialize Disk
Bottom: disk map, barsEach partition as a colored bar with its letter, size, file system, and status. Small partitions such as the EFI System Partition and Recovery Partition appear too.Right-click a bar for volume actions
Black barsUnallocated spaceSpace that belongs to no volume and holds no data
Action menuRescan Disks, Create VHD, Attach VHDFinding newly connected disks, and creating practice virtual disks

When a Technician Uses It

  • A newly installed drive does not appear in File Explorer
  • A drive needs a different letter, or has lost its letter
  • A volume needs to be shrunk to make room, or extended into free space
  • You need to see a disk's layout before reinstalling Windows or replacing a drive

How to Open It

  • Run: diskmgmt.msc
  • Quick Link menu: Windows key + X > Disk Management
  • Computer Management: Storage > Disk Management

Requires administrator rights.

Primary Functions, Step by Step

A. Initialize a new disk. A brand-new disk must be initialized before Windows can use it. Never initialize a disk that already holds data.

  1. Right-click the disk's left block, which shows Not Initialized, and choose Initialize Disk.
  2. Confirm the correct disk is checked. Choose GPT for modern UEFI computers, or MBR for older hardware that does not support UEFI.
  3. Click OK. The disk becomes Online, with all of its space Unallocated.

B. Create and format a volume.

  1. Right-click the black Unallocated bar and choose New Simple Volume.
  2. In the wizard, accept or enter the size in MB.
  3. Assign a drive letter. Without one, the volume will not appear in File Explorer.
  4. Choose the file system (NTFS for Windows), the allocation unit size (Default), and a volume label, leave Perform a quick format checked, and click Finish. The status becomes Healthy.

C. Change a drive letter. Right-click the volume, choose Change Drive Letter and Paths, then Change (or Add if it has none), pick a letter, and click OK. Programs that expected the old letter may need to be pointed at the new one.

D. Shrink or extend a volume. Right-click the volume and choose Shrink Volume, then enter the amount to shrink in MB. To grow a volume, choose Extend Volume. Extend works only into unallocated space directly to the right of the volume on the same disk — which is why the option is often grayed out.

Destructive Actions

Delete Volume, Format, and initializing the wrong disk destroy data. Before any of them, read the disk number, size, and label twice. On a customer's computer, confirm a backup exists first.

Practical Example

The Ticket

"Facilities installed a second drive in my workstation for project files, but it's not in File Explorer."

  1. Open Disk Management. The new drive appears as Disk 1, Not Initialized, with its full capacity Unallocated.
  2. Initialize it as GPT, since the workstation uses UEFI.
  3. Create a New Simple Volume using all the space: NTFS, label Projects, letter P.
  4. Confirm drive P: appears in File Explorer and the user can save a test file.
  5. Record in the ticket: the disk number, partition style, file system, letter, and label.
Lab Task — Practice on a Virtual Disk

A virtual hard disk lets you practice every step above with no risk to a real drive.

  1. Choose Action > Create VHD. Location: C:\Lab\practice.vhdx (create the folder first if needed). Size: 1 GB. Format: VHDX. Type: Dynamically expanding. Click OK.
  2. A new disk appears as Not Initialized. Record its disk number.
  3. Initialize it as GPT.
  4. Create a New Simple Volume: NTFS, label PRACTICE, any free letter. Record the letter and the capacity shown.
  5. Shrink the volume by 200 MB. Record what appears to its right.
  6. Extend the volume back into that space. Record whether Extend Volume was available, and why.

Cleanup: right-click the virtual disk's left block and choose Detach VHD, then delete C:\Lab\practice.vhdx.

Task Scheduler taskschd.msc

Task Scheduler runs programs and scripts automatically — at a set time, at startup, when someone signs in, or when a particular event appears in a log. Windows itself uses it constantly, and so does almost every program that updates itself.

Anatomy of the Window

PartWhat You SeeWhat It Is For
Left pane: Task Scheduler LibraryFolders of tasks. Windows' own tasks live under Microsoft > Windows; tasks from installed programs are often at the top level of the Library.Browsing every scheduled task on the machine
Center top: task listColumns for Name, Status, Triggers, Next Run Time, Last Run Time, and Last Run ResultSeeing what runs, when it last ran, and whether it worked
Center bottom: tabsGeneral, Triggers, Actions, Conditions, Settings, and HistoryEverything about the selected task. Triggers say when; Actions say what.
Right: Actions paneCreate Basic Task, Create Task, Display All Running Tasks, Enable All Tasks History, and, for a selected task, Run, End, Disable, Properties, and DeleteCreating and controlling tasks

Reading Last Run Result: 0x0 means the task completed successfully. 0x41301 means it is running right now. Any other code is worth investigating.

When a Technician Uses It

  • Something happens on a schedule that nobody can explain — a pop-up, a slowdown, a program opening
  • A backup or maintenance job needs to run automatically
  • A scheduled job has stopped running, or is failing
  • Checking for persistence: malware often schedules itself to come back

How to Open It

  • Run: taskschd.msc
  • Computer Management: System Tools > Task Scheduler
  • Windows Tools: Start > All apps > Windows Tools > Task Scheduler

Primary Functions, Step by Step

A. Find out what runs, and when.

  1. Select Task Scheduler Library. Sort by Next Run Time or Triggers.
  2. Select a task. On the Triggers tab, read when it runs. On the Actions tab, read exactly which program it starts.
  3. On the General tab, note the author and which account it runs as.

B. Create a basic task.

  1. Select the folder for the task, then choose Create Basic Task in the Actions pane.
  2. Enter a clear Name and a Description that says who created it and why.
  3. Choose the Trigger: Daily, Weekly, Monthly, One time, When the computer starts, When I log on, or When a specific event is logged. Then set its details.
  4. Choose the Action: Start a program. Browse to the program or script, and add any arguments.
  5. Review the summary and click Finish.

C. Change or stop a task safely. To change the schedule, open Properties > Triggers > Edit. To stop a task without losing it, right-click it and choose Disable — easy to undo, unlike Delete.

D. Check a task's history. Choose Enable All Tasks History in the Actions pane, then use the History tab to see each time a task started, completed, or failed.

Practical Example

The Ticket

"Every morning around nine, a window flashes up and my computer crawls for half an hour. It's been happening since the office manager installed something new last week."

  1. Open Task Scheduler and select the Task Scheduler Library. Sort by Triggers.
  2. Find a task triggered daily at 9:00 AM that was not there before. On its Actions tab, confirm the program it starts.
  3. Check Last Run Result. If it shows 0x41301 during the slowdown, the task is running at that moment.
  4. Find out who owns the task before touching it. Then, with their agreement, move the trigger to after business hours rather than deleting it.
  5. Record the task's name, old and new trigger, and who approved the change.
Lab Task

(1) In the Task Scheduler Library, find one task that is not under the Microsoft folder. Record its name, trigger, action, and Last Run Result. (2) Create a basic task named Lab Reminder: trigger One time, three minutes from now; action Start a program, notepad.exe. Wait for Notepad to open on its own. Record the Last Run Result afterward.

Cleanup: right-click Lab Reminder and choose Delete. Close Notepad.

Device Manager devmgmt.msc

Device Manager lists every piece of hardware Windows knows about and the driver that runs it. It is the first stop for any problem that sounds like "this device stopped working."

Anatomy of the Window

PartWhat You SeeWhat It Is For
Device treeCategories such as Display adapters, Network adapters, Audio inputs and outputs, and Universal Serial Bus controllers. Expand one to see its devices.Finding a specific device
Status iconsA yellow triangle with an exclamation mark means a problem, usually the driver. A down arrow means the device is disabled. Other devices or Unknown device means Windows has no driver for it.Spotting trouble at a glance
Properties: General tabDevice status, including an error code when something is wrongLearning exactly what Windows thinks is wrong
Properties: Driver tabDriver Provider, Driver Date, Driver Version, Digital Signer, and the buttons Update Driver, Roll Back Driver, Disable Device, and Uninstall DeviceManaging the driver
Properties: Details and Events tabsTechnical properties such as Hardware Ids; a history of installs and changesIdentifying an unknown device; seeing when a driver changed
View and Action menusView > Show hidden devices, View > Devices by connection, Action > Scan for hardware changesRevealing disconnected devices; asking Windows to detect hardware again

When a Technician Uses It

  • A device stopped working, especially right after an update
  • A new device is not recognized
  • You need the exact driver version before updating or reporting a problem
  • A device needs to be turned off without unplugging it

How to Open It

  • Run: devmgmt.msc
  • Quick Link menu: Windows key + X > Device Manager
  • Computer Management: System Tools > Device Manager

Viewing works for any user. Changing drivers, including rolling back, requires administrator rights.

Primary Functions, Step by Step

A. Find a problem device and read its status.

  1. Look for a yellow triangle. Device Manager usually expands the category that contains a problem device when it opens.
  2. Right-click the device, choose Properties, and read Device status on the General tab. Common codes: Code 28 means the drivers are not installed; Code 43 means Windows stopped the device because it reported problems.

B. Update a driver. Right-click the device, choose Update driver, then either Search automatically for drivers or Browse my computer for drivers if you downloaded one from the manufacturer.

C. Roll back a driver.

  1. Right-click the device and choose Properties, then the Driver tab.
  2. Click Roll Back Driver. It is available only if a previous driver is stored. Choose a reason when asked.
  3. Restart if prompted, then test the device.

D. Disable, uninstall, and rediscover. Disable Device turns a device off but keeps its driver. Uninstall Device removes it; then Action > Scan for hardware changes makes Windows detect it and reinstall a driver.

E. Reveal hidden devices. Choose View > Show hidden devices. Grayed-out entries are devices Windows remembers but that are not connected right now.

Practical Example

The Ticket

"My webcam worked fine on Friday. Windows installed updates over the weekend, and now Teams says no camera was found."

  1. Open Device Manager and expand Cameras. The webcam shows a yellow triangle.
  2. Open Properties. The General tab shows Code 43. The Driver tab shows a driver date from this weekend.
  3. Click Roll Back Driver, choose the reason that the previous version worked better, and restart.
  4. Test in Teams: the camera works.
  5. Record the old and new driver versions in the ticket, and report the faulty update so it can be paused on similar machines.
Lab Task

(1) Expand Network adapters, open one adapter's Properties, and record its Driver Provider, Driver Date, Driver Version, and whether Roll Back Driver is available. (2) On the Details tab, choose Hardware Ids from the drop-down and record the first line. (3) Choose View > Show hidden devices and record the name of one grayed-out device.

Cleanup: choose View > Show hidden devices again to turn it off. Do not change any driver.

Certificate Manager certmgr.msc

Digital certificates are the credentials that prove a website, a person, or a device is who it claims to be. Certificate Manager shows the certificates stored for the current user — which ones are trusted, who issued them, and when they expire.

Anatomy of the Window

PartWhat You SeeWhat It Is For
Left pane: certificate storesFolders including Personal, Trusted Root Certification Authorities, Intermediate Certification Authorities, Trusted Publishers, and Untrusted Certificates. Each holds a Certificates folder.Each store has a job: Personal holds your certificates; Trusted Root holds the authorities Windows trusts
Center: certificate listColumns for Issued To, Issued By, Expiration Date, Intended Purposes, and Friendly NameSorting by expiration finds the problem fast
Certificate window: General tabWhat the certificate is for, who it was issued to and by, and Valid from … toReading one certificate
Certificate window: Certification Path tabThe chain from the certificate up to a trusted root, and a Certificate status lineProving whether Windows trusts it, and if not, which link is broken

Current User or Local Computer

certmgr.msc opens the Current User stores — certificates for the signed-in person and the programs they run. certlm.msc opens the Local Computer stores, used by Windows services and everyone on the machine, and requires administrator rights. A certificate installed in one is not automatically in the other, which explains many "but I installed it" tickets.

When a Technician Uses It

  • An application, VPN, or Wi-Fi connection reports that a certificate is invalid, untrusted, or expired
  • A user needs a certificate exported for a new computer, or imported from the security team
  • Checking whether an unexpected root certificate has been added — one way attackers intercept encrypted traffic

How to Open It

  • Run: certmgr.msc for the current user; certlm.msc for the local computer
  • Custom console: run mmc, then File > Add/Remove Snap-in > Certificates > Add, and choose My user account or Computer account

Primary Functions, Step by Step

A. Find and read a certificate.

  1. Expand a store, such as Personal, and select Certificates.
  2. Click the Expiration Date column to sort.
  3. Double-click a certificate. On the General tab, read Issued to, Issued by, and the Valid from and to dates.

B. Check whether it is trusted. Open the Certification Path tab. Each level should lead up to a trusted root. The Certificate status line reads "This certificate is OK" when the chain is valid, or describes what is wrong.

C. Export or import. Right-click a certificate and choose All Tasks > Export, or right-click a store and choose All Tasks > Import, then follow the wizard. Import only certificates that come from your organization's security team or a verified source.

Never Add or Delete Roots on a Hunch

A certificate placed in Trusted Root Certification Authorities is trusted for everything it covers. Attackers who can add a root certificate can impersonate websites to that computer. Do not import a root to make an error disappear, and do not delete one without direction — that can break sign-ins, updates, and secure websites.

Practical Example

The Ticket

"Since Monday, the company VPN says my certificate is not valid. Nothing changed on my end."

  1. Open certmgr.msc and go to Personal > Certificates.
  2. Find the certificate issued by the company's certificate authority, with the VPN purpose listed.
  3. Read its Expiration Date: it expired on Sunday. Nothing changed on the user's end — the calendar did.
  4. Do not try to fix it by importing something. Request renewal through the security team's process, then confirm the new certificate appears and the VPN connects.
  5. Record the expiration date and renewal in the ticket, and suggest an expiration reminder.
Lab Task

(1) In Trusted Root Certification Authorities > Certificates, pick any certificate. Record its Issued To, Issued By, and Expiration Date. Explain why Issued To and Issued By match for a root. (2) Open its Certification Path tab and record the Certificate status. (3) Sort Personal > Certificates by Expiration Date and record whether the store is empty, or the earliest expiration date in it.

Cleanup: nothing was changed. Do not import, export, or delete any certificate.

Local Users and Groups lusrmgr.msc

Local Users and Groups manages accounts that exist only on this one computer, and the groups that decide what those accounts may do. It is where least privilege becomes something you configure rather than something you read about.

Not in Windows Home

On a Windows Home edition computer, this snap-in will not load; Windows reports that it may not be used with this edition. On Home, local accounts are managed in Settings > Accounts, or with the net user command from Section 2.3.

Anatomy of the Window

PartWhat You SeeWhat It Is For
Users folderEvery local account, with Name, Full Name, and Description. Built-in accounts such as Administrator and Guest appear here. A down-arrow on the icon means the account is disabled.Creating, disabling, and resetting accounts
Groups folderBuilt-in groups including Administrators, Users, Guests, Remote Desktop Users, and Backup OperatorsGranting rights to many accounts at once
User Properties: General tabCheckboxes: User must change password at next logon, User cannot change password, Password never expires, Account is disabledControlling how an account behaves
User Properties: Member Of tabThe groups this account belongs toSeeing and changing what the account is allowed to do

When a Technician Uses It

  • Setting up a shared, kiosk, or temporary computer with a standard account
  • Checking who is in the Administrators group — a least-privilege audit
  • Disabling an account when someone leaves, without deleting their files
  • Resetting a forgotten local password

How to Open It

  • Run: lusrmgr.msc
  • Computer Management: System Tools > Local Users and Groups

Requires administrator rights.

Primary Functions, Step by Step

A. Create a local account.

  1. Right-click the Users folder and choose New User.
  2. Enter the User name, Full name, and a Description that says who it is for and why.
  3. Enter and confirm a temporary password.
  4. Leave User must change password at next logon checked, so only the user knows the final password.
  5. Click Create, then Close. New accounts are members of Users — a standard account — by default.

B. Change group membership. Right-click the account, choose Properties, then the Member Of tab. Click Add, type the group name, click Check Names, then OK. To see everyone in a group instead, double-click the group in the Groups folder.

C. Disable an account. Open the account's Properties and check Account is disabled. The account and its files remain, but no one can sign in. This is the right first step when someone leaves.

D. Reset a forgotten password. Right-click the account and choose Set Password. Windows warns that resetting can cause irreversible loss of information — such as encrypted files, stored passwords, and personal certificates. Read the warning to the user, and use this only when the password is truly lost.

Practical Example

The Ticket

"A temp is covering the front desk for two weeks. She needs to sign in to the reception computer, but she shouldn't be able to install anything or change settings."

  1. Open Local Users and Groups and create TempFrontDesk with a temporary password, leaving "must change password" checked.
  2. On the Member Of tab, confirm the only group is Users. Standard rights mean she cannot install software or change system settings.
  3. Double-click Administrators and confirm she is not listed.
  4. Give her the temporary password in person, not by email.
  5. Record the account name, groups, and planned end date in the ticket. When the assignment ends, disable the account.
Lab Task

(1) Double-click the Administrators group and record every member. Is that more than this computer needs? (2) Create an account named Lab-Temp1 with "User must change password at next logon" checked. Record the groups shown on its Member Of tab. (3) Disable Lab-Temp1 and record how its icon changed.

Cleanup: right-click Lab-Temp1 and choose Delete.

Performance Monitor perfmon.msc

Task Manager shows what is happening right now. Performance Monitor can show the same kinds of measurements in far more detail and, more importantly, record them over time — which is what you need when a problem happens only in the afternoon, or only on Tuesdays.

Anatomy of the Window

PartWhat You SeeWhat It Is For
Monitoring Tools > Performance MonitorA live graph with a toolbar: the green + (Add Counters), the red X (remove), a graph-type button (Line, Histogram bar, or Report), and Freeze Display. A legend below lists each counter.Watching selected measurements live
CountersIndividual measurements grouped by object: Processor > % Processor Time, Memory > Available MBytes, PhysicalDisk > Avg. Disk Queue Length, Network Interface > Bytes Total/secMeasuring exactly the resource you suspect
Data Collector SetsUser Defined (sets you create) and System, with two built-in sets: System Diagnostics and System PerformanceRecording counters over time, on demand or on a schedule
ReportsUser Defined and System reports produced when a collector set finishesReading the results, including Windows' own analysis

When a Technician Uses It

  • A computer is slow at certain times, and you need evidence of which resource runs out
  • You need a before-and-after comparison to prove a fix worked
  • You need a quick health report from Windows itself

How to Open It

  • Run: perfmon.msc (typing perfmon opens the same tool)
  • Computer Management: System Tools > Performance
  • Windows Tools: Start > All apps > Windows Tools > Performance Monitor

Running the built-in collector sets and the diagnostics report requires administrator rights.

Primary Functions, Step by Step

A. Watch live counters.

  1. Select Monitoring Tools > Performance Monitor.
  2. Click the green +. In the Available counters list, expand an object, select a counter and its instance (such as _Total), and click Add >>.
  3. Add the four counters in the Anatomy table above, then click OK.
  4. Use the graph-type button to switch to Report view, which shows plain numbers that are easier to record.

B. Run a built-in collector set.

  1. Expand Data Collector Sets > System.
  2. Right-click System Performance and choose Start. It collects for about a minute.
  3. When it stops, open Reports > System > System Performance and select the newest report.

C. Generate a System Diagnostics report. Open Command Prompt as administrator and run perfmon /report. Windows collects for about a minute, then opens a report with warnings and a resource overview at the top.

D. Record your own counters over time.

  1. Right-click Data Collector Sets > User Defined and choose New > Data Collector Set.
  2. Name it, choose Create manually (Advanced), then check Performance counter.
  3. Click Add, choose your counters, and set a sample interval such as 15 seconds.
  4. Finish the wizard. Right-click the set to Start it, and again to Stop it. A schedule can be set in its Properties.

Practical Example

The Ticket

"My computer is fine all morning, then from about two o'clock everything is slow. By the time anyone looks at it, it's back to normal."

  1. Create a user-defined collector set with % Processor Time, Available MBytes, Avg. Disk Queue Length, and Bytes Total/sec, sampling every 15 seconds.
  2. Start it at lunchtime and stop it at the end of the day.
  3. Open the log in Performance Monitor. Available MBytes falls close to zero at 2:05 PM and stays there, while disk activity climbs — the computer is running out of memory and swapping to disk.
  4. Compare that time with what the user does at two o'clock. Here, a large report export opens every afternoon.
  5. Record the evidence and recommend more memory or a change to the workflow — with a graph to support it rather than a guess.
Lab Task

(1) Add the four counters from the Anatomy table and switch to Report view. Record each value while the computer is idle. Then open three or four programs and record the values again. Which counter changed most? (2) Run the System Performance collector set and record the top process listed in its report.

Cleanup: remove the counters you added. If you created a user-defined set, right-click it and choose Delete.

Group Policy Editor gpedit.msc

The Local Group Policy Editor sets rules for this computer and its users: security settings, restrictions, and configuration that ordinary Settings screens either do not offer or cannot enforce. In a company, the same kinds of policies are set centrally for every computer in the domain.

Not in Windows Home

The Group Policy Editor is not included in Home editions of Windows. On a domain-joined computer, domain policies are applied after local policy and win when they conflict, so a local change may be overridden.

Anatomy of the Window

PartWhat You SeeWhat It Is For
Computer ConfigurationSettings that apply to the computer, no matter who signs inMachine-wide rules, such as blocking USB storage or locking idle screens
User ConfigurationSettings that apply to the users who sign inPer-user rules, such as hiding parts of Control Panel
Under each: three foldersSoftware Settings, Windows Settings (including Security Settings under Computer Configuration), and Administrative TemplatesAdministrative Templates holds most settings, organized into folders such as System, Windows Components, and Control Panel
Right paneEach setting's name and StateSeeing at a glance what has been configured
Setting windowNot Configured, Enabled, or Disabled; an Options box; and a Help descriptionChanging a setting, and reading exactly what it does before you do

Not Configured means "this policy does not decide." Setting something back to Not Configured is how you undo a policy.

When a Technician Uses It

  • Enforcing a security rule on one computer, such as an automatic screen lock
  • Restricting a kiosk or shared computer, such as blocking USB storage
  • Investigating why a setting cannot be changed — a policy is often the reason it is grayed out

How to Open It

  • Run: gpedit.msc
  • Start search: type Edit group policy
  • Related: secpol.msc opens Local Security Policy, which shows the same Security Settings branch on its own

Requires administrator rights.

Primary Functions, Step by Step

A. Find a setting. Expand the path you need in the left pane. If you do not know where a setting lives, select Administrative Templates > All Settings and sort by name, or use Action > Filter Options to search by keyword.

B. Configure a setting.

  1. Double-click the setting.
  2. Read the Help box first. It explains exactly what Enabled and Disabled do.
  3. Choose Enabled or Disabled, fill in any Options, and click OK.

C. Apply and confirm. Policy refreshes on its own schedule. To apply now, run gpupdate /force in Command Prompt. To confirm what applied, run gpresult /r. Some security settings take effect only after the next sign-in or restart.

D. Undo a setting. Open it again, choose Not Configured, click OK, and run gpupdate /force.

Practical Example

The Ticket

"The library's public catalog computer keeps getting malware from flash drives people plug in. Can we stop it from using USB drives at all?"

  1. Open gpedit.msc on the catalog computer.
  2. Go to Computer Configuration > Administrative Templates > System > Removable Storage Access.
  3. Double-click All Removable Storage classes: Deny all access, read the Help text, choose Enabled, and click OK.
  4. Run gpupdate /force, then insert a flash drive: Windows now denies access.
  5. Record the policy path and setting in the ticket, so the next technician knows why USB drives do not work on this computer.
Lab Task

An unattended, unlocked computer is an open door — a risk you will study in Unit 4. Here you enforce an automatic lock on the lab computer.

  1. Go to Computer Configuration > Windows Settings > Security Settings > Local Policies > Security Options.
  2. Double-click Interactive logon: Machine inactivity limit. Record its current value. Microsoft documents that 0 or blank means the setting is off, and that the limit can range from 0 to 599,940 seconds.
  3. Set it to 120 seconds and click OK. Run gpupdate /force.
  4. Leave the computer untouched for two minutes and record whether it locked. If it did not, sign out, sign back in, and test again.

Cleanup: set the value back to what you recorded in step 2, then run gpupdate /force.

Finish: Build Your Own Console

Technicians rarely open eight separate tools. They build one console that holds the snap-ins they use most and save it for every call.

  1. Press Windows key + R, type mmc, and press Enter. Approve the User Account Control prompt. An empty console opens.
  2. Choose File > Add/Remove Snap-in.
  3. Select Event Viewer, click Add, choose Local computer, and click OK. Repeat for Device Manager and Disk Management.
  4. Click OK. All three snap-ins now appear in one left pane.
  5. Choose File > Save As and save it to the desktop as My Tech Console.msc. Double-click it to confirm it reopens with all three.
Check Your Work

Without looking at your notes, name the snap-in — and its .msc file name — that answers each of these. If you can do all eight, you are ready for the exam's questions on objective 1.4.

  1. "Did my computer restart because of an update, or did it crash?"
  2. "I installed a new drive and it isn't in File Explorer."
  3. "Something opens on my screen at the same time every morning."
  4. "My printer stopped working right after an update."
  5. "The VPN says my certificate has expired."
  6. "Who has administrator rights on this computer?"
  7. "It's only slow in the afternoons, and it's fine when you look."
  8. "Block flash drives on the public kiosk."

Lab 2.6.2 — Command Line Relays

Thursday · In class · 60–90 minutes · Objective 1.5

Purpose

Five relays, each built around a job technicians really do at the command line: finding their way around, tracing a network problem, moving files safely, identifying a machine and its user, and checking a disk. Speed is the hook. Accuracy is the point. Relays 1 through 3 are the core; run 4 and 5 as time allows.

How a Relay Works

  • Teams of three or four, one computer per team.
  • Each step is one leg. One person types; the next person takes the keyboard for the next step; everyone records answers on the team sheet.
  • One point per correct recorded answer. The instructor sets a time limit for each relay.
  • Read the Overview Goal first. It tells you what the whole relay is for, so each command makes sense as part of a job.
Safety Rules for Every Relay
  • Create practice files only inside the folders the steps tell you to make.
  • Run commands that delete, mirror, or format only exactly as written, and only against the practice folder or the lab USB drive.
  • Relay 5 changes a disk. It uses an administrator prompt and the lab USB drive only.

Relay 1 — Find Your Way Around

Overview Goal

Move through the file system, see what is hidden, build and copy a folder, identify the machine, test the network, and look up a command instead of memorizing it. This is the original relay: a tour of the basics you will use on every call.

  1. Navigate. Open Command Prompt. Run cd \ to reach the root of C:, then cd Users\%USERNAME% to enter your own user folder. Run dir to prove where you are. Record the folder path shown in the prompt.
  2. Reveal what is hidden. Run dir /a, which includes hidden and system items. Record one folder that appeared this time and not the first time.
  3. Build and fill. Run md Relay, then cd Relay. Create two small files with echo first> one.txt and echo second> two.txt. Run dir. Record the two file names and their sizes.
  4. Copy it properly. Run cd .., then robocopy Relay Relay-Copy /e. The /e switch includes subfolders, even empty ones. Read the summary table and record how many files were copied.
  5. Identify the machine. Run hostname, then whoami, then winver (which opens a window). Record all three answers.
  6. Test the network. Run ipconfig. Record the IPv4 address, subnet mask, and default gateway. Then run ping followed by the default gateway's address. Record whether replies came back.
  7. Look it up rather than memorize it. Run sfc /?. Find the switch that scans and repairs protected system files. Do not run it. Record the switch and what it does.
  8. Clean up. Run rmdir /s /q Relay and rmdir /s /q Relay-Copy. The /s switch removes the folder's contents, and /q skips the confirmation. Run dir and record that both folders are gone.

Debrief: Which answer in this relay would you have had to look up on a real call, and where would you have found it fastest?

Relay 2 — Network Detective

Overview Goal

Work a "the internet is down" call from the inside out, one layer at a time: this computer's own settings, the local network, name resolution, and the path to the outside world. Each command answers one question, and the order matters.

  1. Read the full configuration. Run ipconfig /all. Record the Physical Address, whether DHCP is enabled, the DHCP server, and the DNS servers.
  2. Test this computer's own network stack. Run ping 127.0.0.1. Record the result. Replies here mean TCP/IP is working on this machine, before any cable or router is involved.
  3. Test the local network. Ping the default gateway you recorded in Relay 1, or read it from step 1. Record the average time.
  4. Test name resolution. Run nslookup www.comptia.org. Record the name and address of the server that answered, and one address returned for the site.
  5. Trace the path. Run tracert -d www.comptia.org. The -d switch skips name lookups so it runs faster. Record the number of hops and whether any hop shows * timeouts. Timeouts on a single hop are often a router that does not answer pings, not a failure.
  6. Measure loss along the path. Run pathping -n -q 10 www.comptia.org. The -q 10 switch sends ten queries per hop instead of the default 100, so it finishes sooner. Record the hop with the highest loss percentage, if any.
  7. See what is connected right now. Run netstat -an. Record one connection in the ESTABLISHED state and one port in the LISTENING state.
  8. Check mapped drives. Run net use. Record what it lists, or that there are no entries.
When Ping Fails

Many networks block ping to the outside world. A timeout does not always mean the destination is down — which is exactly why nslookup and tracert come next. Record what you see either way.

Debrief: A user can reach websites by IP address but not by name. Which step in this relay finds that problem, and what would it show?

Relay 3 — Safe File Mover

Overview Goal

Build a project folder structure, back it up, update the backup with only what changed, and see why one of robocopy's most useful switches is also one of its most dangerous. Moving a user's files safely is a core help-desk task.

  1. Start in a safe place. Run cd /d %USERPROFILE% to go to your own user folder. The /d switch also changes the drive if needed.
  2. Build a structure. Run md Relay3\Projects\Q1, then md Relay3\Projects\Q2. A single md creates every folder in the path. Record how many folders you created with two commands.
  3. Add files. Run echo plan> Relay3\Projects\Q1\plan.txt, echo budget> Relay3\Projects\Q2\budget.txt, and echo notes> Relay3\notes.txt.
  4. List everything. Run dir /s Relay3. Record the Total Files Listed at the bottom.
  5. Make a backup. Run robocopy Relay3 Relay3-Backup /e. Record the Copied count for Files.
  6. Change one file, then back up again. Run echo updated>> Relay3\notes.txt (two arrows add to the file). Then run the same robocopy command again. Record how many files were copied this time, and how many were skipped. Robocopy copies only what changed.
  7. See what mirroring does. Run del Relay3\Projects\Q2\budget.txt. Then run robocopy Relay3 Relay3-Backup /mir. Record the Extras count, and run dir /s Relay3-Backup to record whether budget.txt still exists in the backup.
  8. Clean up. Run cd /d %USERPROFILE%, then rmdir /s /q Relay3 and rmdir /s /q Relay3-Backup. Run dir and record that both folders are gone.
Why Step 7 Matters

/mir makes the destination match the source exactly, which includes deleting anything in the destination that is not in the source. Mirror the wrong way round, or into the wrong folder, and it deletes real data. Read every robocopy command twice before you press Enter.

Debrief: When would you use /e, and when /mir? What would you check before running either on a user's files?

Relay 4 — Machine and User Identity Card

Overview Goal

Collect everything a ticket needs to identify a computer and the person using it — name, version, account, groups, local accounts, and applied policy — then find unfamiliar switches with built-in help instead of guessing.

  1. Computer name. Run hostname. Record it.
  2. Windows version. Run winver. Record the version and OS build.
  3. Who is signed in, and with what rights. Run whoami, then whoami /groups. Record the account name, and whether BUILTIN\Administrators appears in the group list.
  4. Local accounts. Run net user. Record how many accounts are listed. Then run net user followed by one of those account names. Record whether the account is active, when its password was last set, and its local group memberships.
  5. Applied policy. Run gpresult /r. Record the domain or workgroup name, and the Group Policy objects listed under the user settings.
  6. Look up switches. Run chkdsk /? and record the switch that fixes errors and the one that locates bad sectors. Run robocopy /? and record the switch that mirrors a folder.
  7. Write the identity card. As a team, write five lines that could go straight into a ticket's device information: computer name, Windows version and build, user account, administrator or standard, and domain or workgroup.

Debrief: Which of these answers would a user be unable to tell you over the phone, and why does that make the command line faster than asking?

Relay 5 — Disk and System Health

Overview Goal

Check a disk and a system file without changing anything, identify a drive positively before touching it, and only then format it — the discipline that separates a technician from someone who erases the wrong drive. This relay uses an administrator prompt and the lab USB drive.

  1. Open an administrator prompt. Right-click Command Prompt and choose Run as administrator. Record the word that now appears in the window's title bar.
  2. Scan the disk without changing it. Run chkdsk C: with no switches. Without /f it only reports. Record the summary line it ends with.
  3. Verify one system file. Run sfc /verifyfile=C:\Windows\System32\kernel32.dll. This checks a single protected file without repairing anything. Record the result.
  4. Identify the disks. Insert the lab USB drive. Run diskpart, then list disk, then list volume. Record the disk number and the volume letter of the USB drive, and the size that proves it. Type exit to leave diskpart.
  5. Confirm before you format. Have a second teammate read the USB drive's letter and size from step 4 out loud, and match them to File Explorer.
  6. Format the lab USB drive. Run format X: /fs:exFAT /q /v:RELAY5, replacing X with the confirmed letter. Answer the prompt that follows. Record the file system and label reported when it finishes.
  7. Refresh policy. Run gpupdate /force. Record the two completion messages.
On a Real Machine

Never run chkdsk /f or chkdsk /r on a customer's drive without a backup and a plan — on the system drive it schedules itself for the next restart, and on a failing drive it can take hours. And never format any drive you have not identified twice, by letter and by size.

Debrief: Which steps in this relay only read information, and which changed something? How did steps 4 and 5 protect you?

The Winning Team Is Not the Fastest

Teams are scored on correct recorded answers, not finishing order. A team that finishes last with every answer right beats a team that finishes first with half of them. On the exam, the same trade applies.

Lab 2.6.3 — Take-Home: Your Machine, Your Tools

On your own · 1–1.5 hours · Ungraded · Objectives 1.4, 1.5, 1.6

In Unit 1 you inventoried your own machine. This week you operate it. Same computer, three new sets of tools — and by the end you will have a personal reference sheet you will still be using in Unit 6.

Nothing in this lab changes a setting. Every step is read-only: you are looking and recording, not configuring.

Part 1 — What Is This Machine Doing? (about 20 minutes)

  1. Open Task Manager with Ctrl+Shift+Esc. On the Processes tab, sort by CPU and record the top three processes and their percentages. Then sort by Memory and record the top three.
  2. Read the Performance tab. Record your total installed RAM, how much is in use right now, and your CPU's speed and core count.
  3. Check what starts itself. On the Startup tab, record how many programs are enabled and name the two with the highest startup impact.
  4. Run msinfo32 and record the BIOS mode, the system model, and the page-file location.
  5. Open Event Viewer and, in the System log, record the date and Event ID of the most recent Error or Critical entry. If there are none, say so — that is a finding too.

Part 2 — Eight Commands, One Machine (about 25 minutes)

Run each command and record its output in your own notes. Every one is safe and read-only. Check the Practice Safely box in Section 2.4 before you improvise.

  1. hostname — record the computer name
  2. whoami — record the account name, then run it again with the switch that lists group memberships
  3. winver — record the edition, version, and build
  4. ipconfig /all — record your IP address, subnet mask, default gateway, MAC address, and DNS servers
  5. ping your default gateway — record whether replies came back and the average time
  6. nslookup www.cpcc.edu — record the server that answered and the address it returned
  7. net use — record any mapped drives, or note that there are none
  8. gpresult /r — record whether any policies are applied to your machine

For each command, write one line in your own words saying what it told you. That line is what turns eight outputs into eight command cards.

Part 3 — Where Does It Live? (about 20 minutes)

Find each setting below in both Control Panel and the Settings app, and record the exact path to each. Some are easier in one than the other, and noticing which is part of the exercise.

  1. Show file extensions. Turn it on while you are there — it is the one change this lab recommends, and every technician should be running with extensions visible.
  2. Uninstall a program — find the list in both places. Do not uninstall anything.
  3. Set the default printer — find the setting in both places.
  4. Choose what closing the lid does (or, on a desktop, when the display turns off) — and record whether fast startup is on.
  5. Check for Windows updates — find it, and record the last date updates were installed.

Part 4 — Write It Up

One page, in the objective 4.1 ticket format: device information, what you were asked to determine, your progress notes, and a resolution. Your resolution should answer one question in plain language a customer would understand: based on what these tools showed you, is this machine healthy, and what would you check first if it slowed down tomorrow?

Bring It to Class

Bring your write-up and your command notes to Thursday's session. Your Part 2 notes are the reference sheet you will want in front of you during the Command Line Relays, and your Part 3 list is the beginning of the "where does it live" table that Section 2.4 asks you to keep.
