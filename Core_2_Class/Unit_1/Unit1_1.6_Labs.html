Three optional labs we run in class as time permits, and one take-home lab you do on your own machine. None of these is graded. All of them are where this week's reading turns into something you can actually do.

Ungraded Does Not Mean Optional Learning

The labs in this section carry no points. They carry something better: the first time you do a thing is the first time you really understand it. Students who skip the hands-on work can usually recite the difference between FAT32 and exFAT. Students who do it can pick the right one under exam pressure.

Before You Touch Anything — Data Safety

Core 2 work can destroy data faster than a screwdriver ever could. Formatting, partitioning, and installation are permanent operations.

  • Format only drives supplied for the lab or USB drives you own and have emptied
  • Never run a format, partition, or installation on a machine holding data you need
  • Assume anything on a lab machine will be wiped — save nothing there
  • Classroom hardware rules from Core 1 still apply: unplug before opening a case, wear the strap, and no power supply is opened by anyone, ever

Lab 1.6.1 — Ticket Triage

Thursday · In class · 30–45 minutes · Objectives 4.1, 4.7

You will work in pairs. One person plays a customer with a problem and a personality; the other plays the technician. Then you swap.

  1. Take the call. The customer describes the problem in their own words, which will be vague, partly wrong, or both. Ask open-ended questions to narrow it. Do not interrupt.
  2. Restate the issue back to the customer and get their confirmation that you understood it.
  3. Write the ticket: user information, device information, a clear issue description, a category, and a severity.
  4. Add two progress notes describing what you checked, written so another technician could pick up where you stopped.
  5. Write the resolution — what fixed it, specifically. "Fixed it" is not a resolution.
  6. Swap roles and run a second scenario.
Check Your Work

Trade tickets with another pair. If they can tell you exactly what was wrong and what was done without asking you a single question, the ticket is good.

Lab 1.6.2 — File System Face-Off

Wednesday · In class · 45 minutes · Objective 1.1

The 4 GB limit is the kind of fact that sounds arbitrary until you watch a copy fail in front of you.

  1. Format a USB drive as FAT32 on a lab machine. Note how long the format takes and what options you are offered.
  2. Copy a file larger than 4 GB to it. Record the exact error message word for word — the exam describes symptoms, not causes.
  3. Reformat the drive as exFAT and copy the same file. Note the difference.
  4. Reformat as NTFS, then right-click a file on the drive and open Properties, then Security. Note what NTFS gives you that the other two did not.
  5. Test cross-platform behavior if a Mac is available: which of the three drives can the Mac read, and which can it write to?
  6. Record your recommendation for three scenarios: a drive shared between a Windows PC and a Mac, a drive holding company files that need permissions, and a drive that must work in a car stereo.
🔍

Lab 1.6.3 — Will It Run?

Thursday · In class · 30 minutes · Objectives 1.10, 1.3

Customers ask this question constantly. Answering it well is a five-minute skill that makes you look like a professional.

  1. Pick three real applications of different weights — something small, something mid-sized, and something demanding such as a video editor or a current game.
  2. Find each one's published system requirements, minimum and recommended.
  3. Inventory the lab machine: processor, installed RAM, free storage, graphics (integrated or dedicated), and Windows edition and version.
  4. Compare and decide for each application: runs well, runs poorly, or will not install. Say which specific requirement decided it.
  5. Name one impact of installing the demanding application on this machine for each of the four exam categories: device, network, operation, and business.

Lab 1.6.4 — Take-Home: Document Your Own Machine

On your own · 1–1.5 hours · Ungraded · Objectives 1.1, 1.3, 1.10, 4.1

Every technician should be able to inventory a computer in ten minutes. This week you do it on the machine you know best — your own — and write it up the way a help desk would.

Nothing in this lab changes a setting. Every step is read-only: you are looking, not configuring.

  1. Identify the operating system. Press Windows key + R, type winver, and press Enter. Record the edition and version. On macOS, use the Apple menu, then About This Mac. On Linux, run cat /etc/os-release in a terminal.
  2. Record the hardware. Open Settings, then System, then About (or the equivalent on your OS). Record the processor, installed RAM, and system type.
  3. Record storage and file system. Open File Explorer, right-click your main drive, and choose Properties. Record the file system, total capacity, and free space. Repeat for any external or USB drive you have.
  4. Check firmware and security features. Run msinfo32 and record the BIOS mode (UEFI or Legacy) and whether Secure Boot is on. Then run tpm.msc and record whether a TPM is present and its version.
  5. Judge it against Windows 11. Using the requirements in Section 1.3, state whether your machine meets each one, and name the specific requirement that would block an upgrade if any would.
  6. Check one application. Pick an application you actually want to install, find its published requirements, and state whether your machine meets them.
  7. Write it up as a ticket. One page, in the objective 4.1 format: device information, a description of what you were asked to determine, your progress notes, and your resolution — a clear recommendation in language a non-technical customer would understand.
Bring It to Class

Bring your write-up to Thursday's session. We compare machines as a group, and the range across the room — some upgradeable, some not — teaches the requirements faster than any slide.

What These Labs Give You

  • A ticket you have written and had someone else read, before you ever write one for a customer
  • First-hand knowledge of what the 4 GB FAT32 limit looks like when it fails
  • A repeatable method for answering "will this run on my computer?"
  • A complete inventory of your own machine, and a defensible answer about its Windows 11 upgrade path
