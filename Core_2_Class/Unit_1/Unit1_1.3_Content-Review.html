From Hardware to Software

In Core 1 you learned the parts: processor, memory, storage, firmware. None of those parts does anything useful on its own. The operating system is what turns a pile of working hardware into a computer a person can use.

Operating System (OS)

The software that manages a computer's hardware and provides services to applications. It decides which program gets the processor, manages memory, reads and writes files on storage, talks to devices through drivers, and presents the interface the user sees.

In Plain Terms

Think of the operating system as the manager of a busy restaurant kitchen. The cooks, ovens, and fridges are the hardware. The orders coming in are the applications. The manager decides who uses which station, keeps the pantry organized, and makes sure nothing catches fire. Without a manager, the kitchen has everything it needs and still serves no food.

Vendor Life Cycles

Every operating system version has a life span set by its vendor. Over that life span, the vendor gradually stops providing new features, then bug fixes, and finally security patches. Two terms describe where a version sits on that path, and they do not mean the same thing.

End-of-Support (EOS)

The vendor stops providing some or all of its normal support for a version. What continues after EOS depends on the vendor: some keep releasing security patches for a while, some sell paid extended security programs, and some stop everything.

End-of-Life (EOL)

The version is finished. The vendor releases no more updates of any kind — including security patches. The computer keeps working, but every security hole discovered after that point stays open permanently.

The Terms Are Not Standardized

There is no single industry definition of EOS and EOL. Microsoft, Apple, and the Linux distributions each use their own terms and their own schedules. The only reliable answer to "is this system still getting security patches?" is the vendor's own lifecycle page for that exact version.

How Each Vendor Handles It

VendorEnd-of-SupportEnd-of-Life
Microsoft
Windows 10/11		Products on Microsoft's Fixed Lifecycle Policy get about five years of mainstream support (new features, fixes, and security updates), then extended support (security updates only). Windows 10 and 11 also follow the Modern Lifecycle Policy: each yearly Windows 11 feature update is serviced for 24 months on Home and Pro, and 36 months on Enterprise and Education. When a version reaches its end-of-servicing date, the computer must move to a newer feature update to keep receiving security patches.Microsoft calls the final date "end of support." After it, a version receives no more security updates unless the organization buys into the paid Extended Security Updates (ESU) program, which Microsoft describes as a last resort, limited to a maximum of three years. In practice, Microsoft's "end of support" is what the exam calls EOL.
Apple
macOS		Apple publishes no lifecycle dates. In practice, the current macOS version receives full support, and the two previous versions continue receiving security updates for roughly two more years — so an older macOS version can be past active support and still receive security fixes. Apple's own documentation warns that not every known security issue is fixed in those previous versions.A macOS version becomes effectively EOL when Apple quietly stops releasing security updates for it, usually once it falls more than two versions behind. Apple does not announce the date in advance, so technicians should track which versions are still receiving security updates.
Linux
Ubuntu, Red Hat		Each distribution sets its own policy. Ubuntu long-term support (LTS) releases come out every two years and receive five years of free standard security maintenance. Paid Ubuntu Pro extends security coverage to ten years, and its Legacy add-on to fifteen. Red Hat Enterprise Linux provides a ten-year life cycle: five years of Full Support followed by five years of Maintenance Support.When a distribution's final support phase ends, the release is EOL. Short-cycle releases reach it quickly — a non-LTS Ubuntu release is supported for only about nine months — which is why businesses standardize on LTS and enterprise releases.
A Real Example You Will Meet on the Job

Windows 10 reached end of support in 2025. Microsoft offers Extended Security Updates so some Windows 10 machines keep receiving security patches for a limited time, but no new features and no general support. Many businesses still have Windows 10 computers, and part of your job will be explaining to a customer why a system at end of support is a risk and what their options are: upgrade to Windows 11, enroll in ESU as a temporary bridge, or replace hardware that cannot run Windows 11.

What the Exam Expects

CompTIA's objective lists End-of-life (EOL) under vendor life-cycle limitations. On the exam, treat EOL as the point where a version gets no more security patches, making it a security risk to keep running. Know the vendor-specific terms above for the job; answer exam questions with EOL.

Update limitations also matter: older hardware may not be allowed to run a newer OS version, and a device may stop receiving feature updates long before it stops working. Compatibility concerns between operating systems come up constantly — a file system one OS writes may be read-only on another, and an application built for one OS usually will not run on another.

File Systems

A file system is the method an operating system uses to organize and track files on a drive. Choosing the wrong one is a classic support call: "My 6 GB video won't copy to this USB stick."

File SystemNative ToWhat to Know for the Exam
NTFS
New Technology File System		WindowsThe Windows default. Supports file and folder permissions, encryption, compression, and very large files and volumes. Journaled, so it recovers well from crashes.
ReFS
Resilient File System		WindowsDesigned for very large storage and automatic detection and repair of data corruption. Used mainly on servers and high-end workstations, not as the boot drive on a typical desktop.
FAT32
File Allocation Table 32		EverythingReadable by almost every device. Maximum file size of 4 GB. No permissions or encryption.
exFAT
Extensible File Allocation Table		Windows, macOSBuilt for flash drives and memory cards, and most commonly used on external hard drives for compatibility — it works on Windows, macOS, and most Linux distributions. Removes FAT32's 4 GB file limit. The usual answer for a cross-platform USB or external drive.
ext4
Fourth extended filesystem		LinuxThe default on many Linux distributions. Journaled and reliable.
XFS
Extended filesystem		LinuxA high-performance journaled file system suited to very large files. The default on Red Hat Enterprise Linux.
APFS
Apple File System		macOS, iOSApple's current default. Optimized for solid-state drives, with built-in encryption and snapshots.

Which Operating Systems Can Read Which File Systems

A drive is only useful if the computer it is plugged into can read it. Each operating system reads its own file systems, but support for the others varies — and this is behind a lot of "my computer can't see this drive" calls.

File SystemWindowsmacOSLinux
NTFSRead and writeRead onlyRead and write on most current distributions
ReFSRead and write (creating new ReFS volumes is limited to certain editions)NoNo
FAT32Read and writeRead and writeRead and write
exFATRead and writeRead and writeRead and write on most current distributions
ext4No, without extra softwareNo, without extra softwareRead and write
XFSNo, without extra softwareNo, without extra softwareRead and write
APFSNo, without extra softwareRead and writeNo, without extra software
  • Linux reads both. Linux can read its own partitions (ext4, XFS) and Windows NTFS partitions, and most current distributions can write to NTFS as well.
  • Windows reads only its own. Of the Windows and Linux file systems, Windows reads only NTFS and ReFS. It cannot see a Linux ext4 or XFS partition, or a Mac APFS drive, without extra software.
  • macOS reads NTFS but cannot write to it. A Mac can open files on an NTFS drive but cannot save to it without third-party software.
  • FAT32 and exFAT work everywhere. All three operating systems can read and write them, which is why they are the standard choice for flash drives and external drives that move between computers.
Real World: The Dual-Boot Computer

A customer has one computer with both Windows and Linux installed. From Linux, they can open their Windows files on the NTFS partition. From Windows, the Linux partition does not appear at all — Windows does not recognize ext4. To share files in both directions, keep shared files on the NTFS partition or on a separate exFAT partition that both operating systems can read and write.

The 4 GB Question

If a question mentions a single file larger than 4 GB and a drive that "won't take it," the drive is almost certainly FAT32. If the drive also needs to work on both Windows and a Mac, the fix is exFAT. If it only needs to work on Windows, NTFS.

Windows Editions

Windows comes in editions aimed at different users. The exam wants you to know which features each one includes, because "Why can't this computer do X?" often comes down to the edition.

EditionIntended ForKey Points

Domain vs. Workgroup

In a workgroup, every computer manages its own user accounts — fine for a home or a tiny office. In a domain, a central server manages accounts and policies for every computer, so one username and password works on any company machine. Only Pro, Pro for Workstations, and Enterprise can join a domain.

In a business, the domain is run by servers called domain controllers, running Windows Server Active Directory. Every domain-joined Windows workstation is managed through those domain controllers: who can sign in, what each user can access, and which settings and security policies apply to the computer.

Beyond This Course — But Worth Learning

Building and running Windows Server domain controllers is outside the scope of this course. It is important to learn, though: nearly every business network you support will be built on it, and it is the natural next step after A+.

You will work with the workstation side of Active Directory in Unit 5 — joining a computer to a domain, Group Policy, login scripts, and security groups are part of exam objective 2.2.

Upgrade Paths and Hardware Requirements

An in-place upgrade installs the new version over the old one and keeps files, settings, and applications. A clean install wipes the drive and starts fresh. Windows 11 raised the hardware bar considerably:

RequirementWindows 11 Minimum
Processor1 GHz or faster, 2 or more cores, compatible 64-bit processor
Memory4 GB
Storage64 GB
FirmwareUEFI, Secure Boot capable
Security chipTPM 2.0
GraphicsDirectX 12 compatible
Connect It to Core 1

You met UEFI and TPM in Core 1 when you studied firmware. Windows 11 is where those two components stop being optional. A computer that "can't upgrade to Windows 11" is very often missing TPM 2.0 or is set to legacy BIOS mode instead of UEFI.

Installing and Upgrading Windows

Boot Methods

To install an operating system, the computer has to start from something other than the drive you are installing onto. The exam lists these boot methods:

  • USB — a bootable flash drive holding the installation files. The most common method today.
  • Network — the computer starts from a server on the network (PXE boot) and pulls the installation from there.
  • Solid-state/flash drives — any bootable flash-based media.
  • Internet-based — installation files downloaded directly from the vendor during setup or recovery.
  • External/hot-swappable drive — an external drive that can be connected without shutting down.
  • Internal hard drive (partition) — installation files stored on a separate partition of the internal drive.
  • Multiboot — more than one operating system installed on the same computer, with a menu to choose at startup.

Deployment Methods and Types of Installations

Installing Windows comes down to two questions: how the operating system gets onto the computer, and what kind of installation you are performing.

Deployment Methods

MethodWhat It Means
Clean installErase the drive and install fresh. Nothing carries over — files, settings, and applications are all gone.
UpgradeMove a computer from an older version or edition of Windows to a newer one, keeping files, settings, and applications.
Remote network installationInstall across the network from a deployment server rather than from local media such as a USB drive.
Image deploymentCopy a prepared, fully configured system image onto many computers. How businesses set up hundreds of identical machines.
Repair installationReinstall the Windows system files while keeping the user's data and applications. Used when Windows is damaged but the data matters.

Types of Installations

TypeWhat It Means
In-place installationInstall over the existing operating system on the same computer, keeping files, settings, and applications. Upgrades and repair installations are both performed in place.
Zero-touch deploymentThe computer ships straight to the user and configures itself the first time they sign in. No technician touches it.

Special Note: The Tools and Drivers Behind a Windows Installation

Several pieces work behind the scenes during a Windows installation. You will rarely set them up yourself, but you will see them constantly.

  • WinPE (Windows Preinstallation Environment) — a small, stripped-down version of Windows that starts from a USB drive or the network. Windows Setup itself runs inside WinPE, and so do the tools businesses use to deploy images. Every time you boot from installation media, you are in WinPE.
  • WinRE (Windows Recovery Environment) — a repair toolkit built on WinPE. It offers Startup Repair, System Restore, Reset this PC, and a Command Prompt, and it starts automatically when Windows fails to boot several times in a row.
  • Recovery partition — a small, hidden partition on the drive that holds WinRE, and on many manufacturer computers a factory image. It is what lets a user reset the computer to its original state without any installation media.
  • Third-party drivers — some storage controllers, especially RAID and certain NVMe setups, are not recognized by Windows Setup on its own. If the installer reports that it cannot find a drive, choose Load driver and supply the manufacturer's storage driver.
  • Installation media drivers — the drivers stored on, or added to, the installation USB drive before you start. Technicians copy the manufacturer's storage and network drivers onto the media so they are on hand at the Load driver step, and businesses build them directly into their deployment images.

Partitioning: MBR vs. GPT

Before a drive can hold an operating system, it has to be partitioned — divided into sections — and each partition formatted with a file system.

MBR (Master Boot Record)GPT (GUID Partition Table)
AgeLegacyModern standard
Maximum drive size2 TBFar beyond any drive sold today
Partitions4 primary (or 3 primary + 1 extended)Up to 128 in Windows
FirmwareLegacy BIOSUEFI (required to boot Windows 11)

Drive format: a quick format simply creates a new, empty file system. A full format also scans the drive for bad sectors and takes much longer.

Upgrade Considerations

  • Back up files and user preferences before any upgrade. Upgrades usually work. "Usually" is why backups exist.
  • Check application and driver support — will the customer's software and devices still work on the new version (backward compatibility)?
  • Check hardware compatibility — does the machine meet the new version's requirements?
  • Understand feature updates and the product life cycle — Windows receives large feature updates on a schedule, and each version has its own end-of-support date.

Installing Applications

"Will this program run on my computer?" is one of the most common questions a technician answers. Every application publishes two sets of requirements, and the answer comes from comparing both to the machine:

  • Minimum requirements — the least the computer needs for the application to install and run at all.
  • Recommended requirements — what the computer needs for the application to run well.

A computer that meets the minimum but not the recommended requirements will run the application slowly. Check both before you tell a customer "yes."

RequirementWhat to Check Against the Minimum and Recommended Requirements
32-bit vs. 64-bitA 64-bit application needs a 64-bit OS. A 32-bit application usually still runs on 64-bit Windows.
Dedicated vs. integrated graphicsDesign, video, and gaming software may require a separate graphics card rather than graphics built into the processor.
VRAMVideo memory on the graphics card. Demanding graphics applications list both a minimum and a recommended amount.
RAM and CPUMinimum and recommended memory and processor speed.
External hardware tokensSome licensed software requires a physical USB key to run.
StorageFree disk space for the installation and its data.
Application-to-OS compatibilityIs the application built for this operating system and version at all?

How Applications Get Installed

SourceHow It Works
App stores
Microsoft Store, Mac App Store, mobile stores		The store checks the device against the application's requirements before the installation begins. If the device does not qualify, the app will not offer to install. Installation, updates, and removal are handled automatically, so the experience is seamless for the user.
Windows desktop applicationsMost traditional Windows applications install through an installation wizard — a step-by-step setup program, often built on Windows Installer. The same installer is registered with Windows, which is how the application is later modified, repaired, or removed.
Linux desktop applicationsApplications are installed as packages through a package manager, such as apt on Ubuntu or dnf on Red Hat. The package manager also installs any other software the application depends on, and it handles updates and removal the same way.

What the Windows Installation Wizard Does

  1. Presents the end-user license agreement (EULA). The user must accept it before the installation continues.
  2. Asks for the installation location — usually a folder under Program Files, which the user can change.
  3. Copies the installation files to that location.
  4. Installs any necessary drivers the application needs to work with hardware.
  5. Requests administrator permission through User Account Control (UAC). Installing software changes the system, so Windows asks for approval — and a standard user needs an administrator's password. Depending on the installer, this prompt appears when setup first starts or just before the files are copied.

Modify, Repair, and Uninstall

Installed applications appear in Settings, then Apps, then Installed apps, and in Control Panel under Programs and Features. Selecting one reopens its installer with up to three options:

OptionWhat It DoesWhen to Use It
ModifyAdds or removes optional parts of the application.The customer needs a feature that was not installed the first time.
RepairReplaces missing or damaged application files with fresh copies from the installer.The program is malfunctioning after installation. Try this before uninstalling.
UninstallRuns the wizard in reverse, removing the application's components from the system.The application is no longer needed, or a full reinstall is required.
Uninstalling Does Not Always Remove Everything

Most programs remove all of their components when uninstalled, but some leave files behind — settings and data in the user's profile folder, or entries in the Windows Registry. Those leftovers can carry an old problem into a fresh reinstall. When a reinstall does not fix the issue, check for leftover folders before assuming the application itself is at fault.

Distribution methods: physical media or a mountable ISO file (a single file that acts like a disc), a downloadable package, or image deployment where the application is built into a standard company image.

Think Past the Install Button

The exam lists four impact considerations for any new application: the impact on the device (performance, storage), the network (bandwidth, updates), operation (does it change how people work?), and the business (cost, licensing, support). A technician who asks these questions before installing prevents the problems that show up after.

Cloud-Based Productivity Tools

Most organizations now run their email, files, and collaboration from the cloud — Microsoft 365 and Google Workspace are the two you will meet most. Setting them up for users is a routine help-desk task.

  • Email systems — hosted email accounts configured on computers and phones.
  • Storage with sync/folder settings — services such as OneDrive and Google Drive keep chosen folders synchronized between the computer and the cloud. You decide which folders sync.
  • Collaboration tools — spreadsheets, videoconferencing, presentation tools, word processing, and instant messaging, often with several people editing at once.
  • Identity synchronization — the company's user accounts are synchronized to the cloud, so a user signs in to everything with one username and password.
  • Licensing assignment — cloud apps are licensed per user. An administrator assigns a license to each account, and a user without one cannot use the app.

Documentation and Support Systems

Every problem a help desk handles lives in a ticketing system. A ticket is the permanent record of what went wrong, what was done, and how it ended. If it isn't in the ticket, as far as the business is concerned, it didn't happen.

Ticket ElementWhat Goes There
User informationWho reported it and how to reach them
Device informationWhich computer or device, identified by asset tag or name
Description of issuesWhat is wrong, in clear terms
CategoriesHardware, software, network, account — used for routing and reporting
SeverityHow badly it affects the user or business
Escalation levelsWhich support tier owns it, and when it moves up
Clear, concise written communicationThe issue description, progress notes, and issue resolution

Write It for the Next Technician

A good ticket lets someone who has never seen the problem pick it up and continue. "Fixed it" is not a resolution. "Replaced the network cable at the desk; user confirmed internet access restored" is. Every Ticket of the Day this term practices exactly this.

A ticket is also a living document. It is updated from the moment it is opened until it is closed, and every entry is time-stamped with who made it. That record does not disappear when the problem is fixed: the organization uses tickets for auditing and compliance — proving what was done, by whom, and when, showing that service-level agreements were met, and demonstrating to auditors that regulated systems and data were handled correctly. Never delete or rewrite an earlier entry. If something changes, add a new note.

Asset Management

Organizations track every device they own through inventory lists and a configuration management database (CMDB). Each device carries an asset tag or ID. Asset records follow the procurement life cycle from purchase to disposal, and record warranty and licensing details and the assigned user.

Types of Documents

  • Incident reports — a formal record of a significant event, such as a security breach or an outage.
  • Standard operating procedures (SOPs) — step-by-step instructions for routine tasks, including a software package's custom installation procedure.
  • New-user onboarding and user off-boarding checklists — everything that must be set up for a new employee, and everything that must be removed or recovered when one leaves.
  • Service-level agreements (SLAs) — commitments on response and resolution times, either internal (IT to the rest of the company) or external/third-party (a vendor to the company).
  • Knowledge base articles — written solutions to known problems, so no one solves the same problem twice from scratch.

Difficult Customers and Situations

Do not argue or become defensive. Do not dismiss the customer's issue or be judgmental. Clarify what they are telling you: ask open-ended questions to narrow the problem, restate the issue in your own words, and confirm you understood. And use discretion afterward — a difficult customer is not a story for social media.

Unit 1 Content Recap

  • The operating system manages hardware and serves applications; know the workstation and mobile OS families by name
  • End-of-support and end-of-life mean different things to different vendors; at end-of-life there are no more security patches — the machine still runs, but its security holes stay open
  • FAT32 cannot hold a file over 4 GB; exFAT is the cross-platform flash answer; NTFS is the Windows default; APFS, ext4, and XFS belong to macOS and Linux
  • Linux can read both NTFS and its own ext4 and XFS partitions; Windows cannot read Linux or Mac partitions without extra software; FAT32 and exFAT work on all three

  • Know the deployment methods (clean install, upgrade, remote network installation, image deployment, repair installation) and the installation types (in-place, zero-touch) — and what WinPE, WinRE, and the recovery partition do
  • MBR tops out at 2 TB and 4 primary partitions; GPT is the modern standard and requires UEFI to boot
  • Check both minimum and recommended requirements, and the impact on device, network, operation, and business, before installing an application
  • App stores check requirements before installing; Windows desktop apps use an installation wizard; Linux uses packages; use Repair before uninstalling a malfunctioning program
  • A good ticket lets the next technician continue the work without asking you anything, and it stays on record for auditing and compliance
  • Listen, clarify, set expectations, document, and follow up
