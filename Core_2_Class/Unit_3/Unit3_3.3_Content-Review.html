Part 1 — Windows on a Network (Objective 1.7)

A computer that cannot reach the network cannot do its job. Objective 1.7 is about four things: where the computer's account lives, what address it uses, how it connects, and what its firewall allows.

Domain or Workgroup

Workgroup

A peer-to-peer arrangement. Every computer keeps its own list of user accounts, and sharing is arranged machine by machine. Fine for a handful of computers; unmanageable beyond that.

Domain

A centrally managed network. Accounts, permissions, and policy live on a server, and a user signs in to the domain rather than to one computer. Windows Home editions cannot join a domain.

The difference shows up in the resources people actually use:

  • Shared resources — folders and devices made available to other users on the network
  • Printers — installed once on a print server and offered to everyone, rather than added machine by machine
  • File servers — central storage for departmental files, backed up on a schedule
  • Mapped drives — a drive letter that points to a folder on a server, so S: means the same thing on every computer
Connect It to Unit 1

This is why Windows editions mattered. A Home edition cannot join a domain, which means it cannot receive Group Policy, cannot use a domain account, and cannot be managed centrally. The dental office in Section 1.3 that bought Home laptops ran into exactly this.

Network Paths in File Explorer

Shared resources are reached by a network path in the form \\servername\sharename. Typing that path into File Explorer's address bar opens the share directly, which is often faster than hunting through Network. The same path is what net use maps to a drive letter.

Static or Dynamic

Dynamic addressing lets a DHCP server hand out the address automatically. This is the default and the right answer for nearly every workstation, because nothing has to be tracked by hand.

Static addressing means a technician types the address in. Use it when something must always be found at the same address — a network printer, a server, or a device other computers are configured to reach.

The symptom that gives it away: a computer with an address starting 169.254 assigned itself an APIPA address because it asked for a DHCP address and got no answer. That is not a "bad IP address" problem; it is a "cannot reach the DHCP server" problem, and the cable, the switch port, or the DHCP service is where you look.

Public and Private Network Profiles

When Windows joins a network it asks whether the network is public or private, and the answer changes the firewall rules. On a private network, discovery and file sharing are allowed, because you trust the other machines. On a public network — an airport, a hotel, a coffee shop — the computer hides itself and blocks sharing.

A Real Example You Will Meet on the Job

A user cannot see the shared folder on a colleague's laptop in the same office, and both machines have internet access. Check the network profile before anything else. If one laptop joined the office Wi-Fi as Public, Windows is blocking discovery and sharing exactly as designed. Switching that connection to Private fixes it in seconds — and switching a coffee-shop connection to Private is the mistake that exposes the machine later.

Local Firewall Settings

The local OS firewall decides which traffic is allowed in and out of this computer. Two ideas carry the objective:

  • Application restrictions and exceptions — allowing a specific program to communicate, rather than opening a port to everything. This is the usual fix when a line-of-business application cannot reach its server.
  • Configuration — rules are set per profile, so a rule that applies on a private network may not apply on a public one. A "it works at the office but not at home" complaint often ends here.

Proxy Settings and Metered Connections

A proxy sits between the computer and the internet, forwarding and often filtering web requests. Many organizations require one, and a wrong proxy setting produces a machine that reaches internal resources but not the web — or the reverse.

A metered connection tells Windows that data costs money. Windows then limits background activity such as large updates and sync. Set it on a cellular hotspot; forget it is set, and you have a machine that mysteriously stops receiving updates.

Your Unit 2 Commands Are the Diagnosis

Everything above is diagnosed with commands you already know. ipconfig /all shows the address, mask, gateway, and DNS in one screen — and reveals a 169.254 address immediately. ping the gateway to test the local network, then ping an outside address to test beyond it. nslookup tests name resolution when addresses work and names do not. net use shows mapped drives. Unit 2's commands are Unit 3's troubleshooting method.

Part 2 — macOS (Objective 1.8)

You do not need to become a Mac expert. You need to do on a Mac the same things you already do on Windows: install and remove software, find a setting, back it up, encrypt it, and rescue it when something hangs.

In Plain Terms

Every task in this section has a Windows twin you already know. System Preferences is Control Panel. Finder is File Explorer. Terminal is Command Prompt. Disk Utility is Disk Management. Time Machine is a backup job. Force Quit is End task. Learn the pairs, not the platform.

Installing and Uninstalling Applications

File TypeWhat It Is
.dmgA disk image. Double-clicking mounts it like a drive; you then drag the application into the Applications folder.
.pkgAn installer package that runs a guided installation, closer to a Windows setup program.
.appThe application itself. On macOS an application is a bundle that looks like a single file.

The App Store is the managed alternative: software is installed and updated through Apple's store with no file to download by hand. Uninstalling is usually just dragging the application from Applications to the Trash — there is no Programs and Features equivalent for most software, though some suites ship their own uninstaller.

System Preferences

System Preferences is where macOS settings live. The exam names Displays, Networks, Printers, Scanners, Privacy, Accessibility, and Time Machine. Apple renamed this System Settings in recent macOS versions; both names refer to the same place, and the exam uses System Preferences.

Tools and Best Practices

  • Disk Utility — erase, format, partition, and repair disks. The Disk Management of macOS.
  • FileVault — full-disk encryption. The BitLocker of macOS, and it will come back in Unit 5.
  • Terminal — the command line. It is a Unix shell, so the Linux commands in Part 3 largely work here too.
  • Force Quit — closes an application that has stopped responding.
  • Apple ID and corporate restrictions — an Apple ID ties a Mac to a person's purchases and iCloud. In a managed environment, organizations restrict what a personal Apple ID may do on a company machine.
  • Best practices — backups (Time Machine), antivirus, updates and patches, and Rapid Security Response, Apple's mechanism for pushing urgent security fixes without a full OS update.
A Real Example You Will Meet on the Job

A designer's Mac is running slowly and an application has frozen. You open Force Quit to close the frozen application, then Activity Monitor — the Task Manager of macOS — to see what is consuming the processor. If the drive is nearly full, Disk Utility confirms capacity. Three tools, all with a Windows twin you learned in Unit 2.

Editors, Configuration Files, and Components

nano is the text editor the exam names. Linux configuration lives in plain text files, which is the single biggest difference from Windows: where Windows has a registry, Linux has files you can read with cat and edit with nano.

FileWhat It Holds
/etc/passwdThe local user accounts
/etc/shadowThe encrypted passwords for those accounts
/etc/hostsLocal name-to-address mappings, checked before DNS
/etc/fstabWhich filesystems are mounted at startup, and where
/etc/resolv.confWhich DNS servers the system uses

Three OS components round out the objective: the kernel, the core of the operating system; the bootloader, which loads the kernel at startup; and systemd, which starts and manages services once the system is running. The root account is the full administrator — which is why sudo, not a root login, is the normal way to work.

Linux Does Not Ask Twice

rm deletes immediately, with no Recycle Bin and no confirmation. Combined with sudo, it will remove system files just as willingly as your own. In NETLAB this costs you nothing. On a production server it costs somebody their weekend.

Part 4 — The Basics of Scripting (Objective 4.8)

A script is a text file of commands that runs in order. Everything in a script could be typed by hand; the value is that it runs the same way every time, on every machine, without a technician being present.

ExtensionLanguageRuns On
.batWindows batch file — command-prompt commands in a fileWindows
.ps1PowerShell — Microsoft's current scripting languageWindows (and cross-platform PowerShell)
.vbsVBScript — older Microsoft scripting, still found in legacy environmentsWindows
.shShell script — Linux and macOS terminal commands in a fileLinux, macOS
.jsJavaScriptBrowsers and other hosts
.pyPythonWindows, Linux, macOS

Use Cases

The exam lists these, and each one is a job someone is doing by hand somewhere right now:

  • Basic automation — any repeated sequence of steps
  • Restarting machines — on a schedule, or across a set of computers at once
  • Remapping network drives — the sign-in script that gives every user the same S: drive
  • Installation of applications — installing the same software on many machines identically
  • Automated backups — copying data on a schedule without anyone remembering to
  • Gathering of information or data — collecting an inventory from every machine on the network
  • Initiating updates — starting patch installation at a chosen time

You Have Already Written Half a Script

In the Unit 2 take-home lab you ran eight commands and recorded what each returned. Put those same eight lines in a text file, save it as inventory.bat, and you have automated the information-gathering use case — the machine now does in two seconds what took you twenty-five minutes. That is the whole idea, and it is why scripting sits in Domain 4.0 with the rest of the operational procedures rather than with the operating systems.

Other Considerations

A Script Is Someone Else's Commands Running as You

CompTIA names three risks, and all three are real:

  • Unintentionally introducing malware — a downloaded script is executable code from a stranger, and it runs with your permissions
  • Inadvertently changing system settings — a script written for a different environment can change configuration you depended on
  • Browser or system crashes from mishandling resources — a badly written loop can consume memory or processor time until the machine stops responding

The professional habit: read a script before you run it, test it on one machine before a hundred, and never run a script you cannot explain line by line.

Unit 3 Content Recap

  • Domain membership means central accounts, policy, and managed resources; a workgroup manages each machine separately
  • Four client settings carry objective 1.7: IP address, subnet mask, default gateway, and DNS — static when something must always be found, dynamic everywhere else
  • An address starting 169.254 means the DHCP request got no answer
  • The public or private network profile decides what the firewall allows, and explains most "I can't see the shared folder" tickets
  • macOS pairs to Windows one tool at a time: System Preferences, Finder, Terminal, Disk Utility, Time Machine, FileVault, Force Quit
  • macOS applications arrive as .dmg, .pkg, or .app, or through the App Store; the system folders are /Applications, /Users, /Library, /System, and /Users/Library
  • Linux commands group by job: files, filesystem, administration, packages, network, and information
  • Where Windows has a registry, Linux has readable configuration files under /etc
  • sudo runs one command as an administrator; root is the full administrator account
  • Script types: .bat, .ps1, and .vbs on Windows; .sh on Linux and macOS; .js and .py across platforms
  • Scripts save enormous time and can introduce malware, change settings, or crash a system — read before you run
