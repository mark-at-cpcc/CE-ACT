Unit 2 was one operating system and its tools. This unit is three — Windows on a network, macOS, and Linux — plus your first look at the scripts that let a technician do the same job a hundred times without doing it a hundred times.

Start With the Pre-Assessment

The Section 3.2 Pre-Assessment is an independent activity you complete on your own. Finish it by the end of Tuesday, the first day of the unit, before you begin the reading and videos, and do not study for it first. Expect the macOS and Linux questions to feel unfamiliar — that is the point of a diagnostic.

Learning Objectives

After completing this unit, you will be able to:

  1. Configure a Windows client's IP addressing, subnet mask, gateway, and DNS settings, choosing between static and dynamic assignment
  2. Distinguish a domain-joined computer from a workgroup computer, and describe how shared resources, printers, file servers, and mapped drives differ between them
  3. Establish and troubleshoot wired, wireless, VPN, and cellular network connections, including proxy settings and metered connections
  4. Configure local firewall settings, including application restrictions and exceptions, and apply the right public or private network profile
  5. Describe the macOS features, tools, and system folders on the exam, and explain how applications are installed and removed on macOS
  6. Identify and use the Linux commands, configuration files, and OS components on the exam
  7. Explain the basics of scripting — the script file types, common use cases, and the risks of running a script you did not write
Technical Overview

Unit 3 addresses CompTIA A+ Core 2 (220-1202) Domain 1.0 Operating Systems — objectives 1.7 (configure Microsoft Windows networking features on a client/desktop), 1.8 (common features and tools of macOS), and 1.9 (common features and tools of the Linux client/desktop) — and Domain 4.0 Operational Procedures, objective 4.8 (the basics of scripting). Instruction covers domain versus workgroup membership, client network configuration, local OS firewall settings, VPN, wireless, wired and WWAN connections, proxy settings, public versus private network profiles, network paths in File Explorer, and metered connections; macOS installation file types, system folders, System Preferences, Disk Utility, FileVault, Terminal, Force Quit, and the Apple ID; Linux file, filesystem, administrative, package-management, network, and informational commands, the nano text editor, common configuration files, and OS components; and script file types, scripting use cases, and scripting risks.

In Plain Terms

A technician is rarely allowed to work on only one kind of computer. The graphic designer has a Mac, the web server runs Linux, and everything else runs Windows — and all of them have to reach the same network and the same printer.

This unit teaches you to get a Windows computer onto a network and keep it there, then shows you that macOS and Linux do the same jobs with different names in different places. Once you see that the jobs are the same, a Mac stops being intimidating and becomes just another machine with a different menu.

Why This Unit Comes Next

You finished Unit 2 able to operate one Windows computer. Almost no computer works alone. Objective 1.7 is where the machine you learned to run joins the network it has to live on, and it builds directly on the command line you just learned — ipconfig, ping, and nslookup stop being commands to memorize and become the way you actually diagnose a connection.

macOS and Linux arrive in the same unit on purpose. You have just spent a unit learning where Windows keeps its settings and how its command line works. That knowledge is the hook: macOS keeps settings in System Preferences, Linux keeps them in text files under /etc, and all three have a terminal where the same kinds of tasks get done. Learning them side by side takes far less time than learning each one cold.

Scripting closes the unit because it is where the three operating systems meet. A .bat or .ps1 file automates Windows, a .sh file automates Linux and macOS, and .py runs on all three.

You Already Met Some Linux

NETLAB Lab 05 in Unit 2 had you run commands in both a Windows prompt and a Linux terminal. You have already used a Linux shell once, guided step by step. This unit names what you were doing.

How This Unit Is Graded

Three things are graded: the NETLAB labs (3.8), the reflection (3.9), and the unit test (3.10). Each is worth 100 points, awarded in full when it meets the completion standard on that item's page. Work that falls short is returned for revision and resubmitted for full credit — it is not partially scored.

Everything else in this unit is ungraded: the pre-assessment, your reading and video notes, the practice questions, and the labs. They are still expected, and they are where the learning actually happens — the graded items only measure it.

Core 2 Passes at 700, Not 675

Core 1 passed at 675 out of 900. Core 2 passes at 700. Because the scale starts at 100 rather than zero, 700 works out to about 75% of raw points — not the roughly 72% you needed in Core 1.

That difference matters. A student who passed Core 1 comfortably at 73% would fail Core 2 with the same performance. Aim higher from day one.
