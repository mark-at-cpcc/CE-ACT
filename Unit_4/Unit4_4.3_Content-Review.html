Wireless Media

Unit 3 focused on wired media — the physical cabling that carries a signal from one point to another. This unit shifts to wireless media and to logical networking (how traffic is organized, addressed, and routed) rather than physical networking (the actual cables and connectors carrying it).

Wireless media carries signals as radio waves through the air instead of over a cable. This unit covers the wireless standards and technologies — from short-range to satellite — a technician needs to identify and configure.

802.11 Frequencies and Channels

Wi-Fi operates primarily in the 2.4 GHz and 5 GHz bands, with newer standards adding 6 GHz. Lower frequencies (2.4 GHz) travel farther and penetrate walls better but are more crowded and slower; higher frequencies (5 GHz and 6 GHz) offer more bandwidth and less interference at the cost of shorter range. Each band is divided into channels, and choosing a channel with less overlap from neighboring networks reduces interference.

Network Services

A network is only as useful as the services running on top of it. This section covers the services a technician is expected to recognize, configure at a basic level, and troubleshoot.

DNS (Domain Name System)

DNS translates human-readable domain names (like a website address) into the IP addresses computers actually use to communicate. Without DNS, every device on the internet would need to be reached by memorized IP address instead of a name.

DNS is like the phone book for the internet. Just as a phone book lets you look up a person's name to find their phone number instead of memorizing every number in town, DNS lets you type a name (like a website address) and get back the numeric IP address behind it — so people never have to memorize strings of numbers to reach the sites and services they use every day.

DHCP (Dynamic Host Configuration Protocol)

DHCP automatically assigns IP addresses, subnet masks, default gateways, and DNS server addresses to devices as they join the network, drawing from a defined pool of available addresses and leasing them out for a set period of time. A DHCP reservation ties a specific device (by MAC address) to the same IP address every time, combining the convenience of automatic assignment with the predictability of a static address.

The DHCP Process: DORA

Every time a device joins a network and needs an address, it goes through a four-step exchange with the DHCP server known by the acronym DORA:

  • Discover — the joining device broadcasts a request to the entire local network, asking "Is there a DHCP server out there?" It doesn't know the server's address yet, so this message goes to everyone.
  • Offer — a DHCP server that hears the request responds directly to the device with an offer: a specific IP address, along with the subnet mask, default gateway, and DNS server it would provide.
  • Request — the device replies, formally requesting that specific offered address. (On a network with more than one DHCP server, this step also tells every other server that its offer was not accepted.)
  • Acknowledge — the server confirms the assignment, and the device configures itself with the address and begins using the network.

The Leasing Process: an assigned address is not permanent — it is leased for a set period of time. A common default lease length is 24 hours, but that duration is configurable and is often shortened in highly transient environments where devices come and go constantly — a busy mall's guest Wi-Fi, for example, might use a lease as short as 30 minutes so addresses free up quickly for the next wave of visitors. As a lease approaches its expiration, the device attempts to renew it directly with the server that issued it, well before time runs out. If the device is renewed successfully, the same address continues uninterrupted; if the original server can't be reached, the device eventually restarts the full DORA process to obtain a new lease.

DHCP Exclusions

A DHCP exclusion is a range of addresses inside a scope that the DHCP server is told never to hand out. The addresses still belong to the subnet, but the server skips over them when assigning leases, leaving them free for devices that are configured manually.

This exists because some devices need a fixed, predictable address that never changes — routers, switches, servers, and network printers are the usual examples. If those addresses stayed in the assignable pool, the DHCP server could hand one out to a random laptop and create an address conflict with the device already using it. Excluding the range prevents that collision entirely. A common setup is a scope covering an entire subnet with the first block of addresses excluded and reserved for infrastructure, and everything above that left available for DHCP clients.

Note the difference between an exclusion and a reservation: an exclusion tells the server not to assign those addresses at all, leaving them for manual configuration, while a reservation has the server assign one specific address to one specific device every time based on its MAC address.

Important Point

Remember APIPA from the previous unit? This is exactly where it comes back in. If a device is set to obtain its address dynamically and no DHCP server answers its Discover broadcast, the DORA process never completes — and Windows doesn't just leave the device with no address at all. Instead, it automatically self-assigns an APIPA address in the 169.254.0.0/16 range so the device can still communicate with other APIPA-assigned devices on the same local segment, even though it has no real network or internet access. Seeing a 169.254.x.x address on a Windows device is one of the clearest signs a technician will encounter that DHCP failed somewhere along the way.

NTP (Network Time Protocol)

NTP synchronizes the clocks of devices across a network to a common, accurate time source. A device configured to use NTP periodically checks in with a time server and adjusts its own clock to match, keeping every machine on the network within milliseconds of the same time.

This matters more than it first appears. When a technician reviews logs from several devices to trace a problem, those logs are only useful if the timestamps line up — otherwise there's no way to tell what happened first. Accurate time is also required for authentication systems, certificate validation, scheduled tasks, and backups, all of which can fail outright when a device's clock drifts too far from the rest of the network.

Database Server

In its most basic form, a database server is a computer whose job is to store organized collections of data and hand out or update that data when other systems ask for it. Rather than each application keeping its own separate copy of information, the database server holds one authoritative set that many clients can query at the same time.

Think of a store's inventory: the point-of-sale register, the online storefront, and the back-office reporting tool all need to know the same stock numbers. Each one sends a request to the database server, which looks up or updates the record and returns the result — so a sale rung up at the register is immediately reflected everywhere else. The database server also handles who is allowed to read or change which records, and works to keep the data accurate when many requests arrive at once.

Other Core Services You Should Recognize

  • File and print servers — centralize storage and shared printer access for a network of users.
  • Mail servers — send, receive, and store email for an organization.
  • Web servers — host and serve websites and web applications.
  • Proxy servers — sit between clients and the internet, filtering, caching, or logging traffic.
  • Load balancers — spread incoming traffic across multiple servers so no single server is overwhelmed.
  • Syslog Servers — a centralized system that receives and stores log messages sent from routers, switches, firewalls, and other network devices, giving a technician one place to review activity and troubleshoot issues instead of checking each device individually.
  • SCADA / legacy / embedded / IoT devices — specialized and often older systems that still need to be identified and secured on a modern network.

Installing and Configuring a SOHO Network

A SOHO (Small Office/Home Office) network is typically built around a single all-in-one device that combines a router, switch, access point, and basic firewall. Installing and configuring one correctly is a core, hands-on A+ skill.

SOHO Wireless Security Basics

  • Change the default administrator password immediately — default credentials are one of the most common causes of unauthorized access.
  • Use WPA3 (or WPA2 if WPA3 isn't available) for wireless encryption. Avoid WEP and open networks for anything beyond a public guest network.
  • Change the default SSID if it reveals the router make/model, and consider disabling SSID broadcast only if that fits the environment's needs.
  • Enable the built-in firewall and disable remote administration unless it's specifically required.
  • Keep firmware updated to patch known vulnerabilities.
Common Exam Trap

WPS (Wi-Fi Protected Setup) is convenient — a button press or PIN to join a network — but its PIN method has known vulnerabilities. Many security-conscious SOHO configurations disable WPS entirely rather than relying on it.

Latency vs. Jitter

Latency is how long it takes a packet to travel from source to destination — a single delay measurement. Jitter is the variation in that delay from one packet to the next. A connection can have high latency but low jitter (consistently slow, but predictable), or low latency but high jitter (usually fast, but unpredictable) — and it's jitter, not raw latency, that tends to make voice and video calls sound choppy.

Virtual Networking

Not every network boundary is a physical cable. Modern networks are frequently divided and protected using virtual constructs that live in software and hardware configuration rather than in a separate set of wires.

On a typical LAN with no VLANs configured, every host is part of one single network. Every device can communicate with every other device, and every device sees the broadcast traffic every other device sends — there's no separation at all. Layer 3 network switches ship from the factory with every port assigned to VLAN 1, the default VLAN, which is exactly this flat, everyone-sees-everyone arrangement. A technician can reconfigure individual ports to belong to a different VLAN instead — for example, moving a set of ports onto VLAN 10 — and from that point on, only other ports also assigned to VLAN 10 can communicate with them directly. A device on VLAN 10 and a device still on VLAN 1 can no longer see each other's traffic or talk to each other without a router or Layer 3 device routing between the two VLANs.

VLAN (Virtual Local Area Network)

A VLAN divides a single physical switch into multiple logical broadcast domains. Devices on different VLANs cannot communicate directly, even if they're plugged into the same physical switch, unless a router or Layer 3 device explicitly routes traffic between them. This is how an organization keeps, say, guest traffic and accounting traffic on the same hardware but fully separated from each other.

Why Segment with VLANs?

VLANs reduce broadcast traffic (smaller broadcast domains mean less noise for every device to process), improve security (a compromised device on one VLAN can't directly reach devices on another), and organize traffic by function or department rather than by physical location. A single managed switch can host dozens of VLANs, each behaving as if it were its own separate physical switch. These smaller broadcast domains are known as subnets — each VLAN typically corresponds to its own subnet, with its own range of IP addresses.

For example, a single office LAN might be divided into four job-specific VLANs:

  • VLAN 10 — Accounting: keeps financial systems and records isolated from the rest of the office.
  • VLAN 20 — Sales and Marketing: separates day-to-day staff traffic from more sensitive departments.
  • VLAN 30 — Servers/IT: isolates backend infrastructure so only authorized traffic reaches it.
  • VLAN 40 — Guest Wi-Fi: gives visitors internet access with no path at all into any internal resource.

Remote Access Technologies

VPN (Virtual Private Network)

A VPN creates an encrypted tunnel across an untrusted network — almost always the public internet — so that traffic inside the tunnel is protected from anyone intercepting it along the way.

VPN TypeWhat It ConnectsTypical Use
Client-to-siteA single remote user's device to an organization's internal networkAn employee working from home reaching office resources
Site-to-siteTwo entire networks to each otherConnecting a branch office network to the main office network permanently
VLANs vs. VPNs, in One Line

A VLAN separates traffic that's already inside a LAN — VLAN traffic cannot be routed onto the internet. A VPN protects traffic coming from the WAN onto the LAN. So one protects individualized traffic on a LAN, and the other protects remote traffic tunneled in from the WAN onto the LAN.

SSH (Secure Shell)

SSH is an encrypted protocol that gives a technician a remote command-line session with a device, over TCP port 22 by default. Once connected, the technician types commands directly into that remote device exactly as if they were sitting in front of it, without ever leaving their own desk.

Why SSH Matters for Core Infrastructure

Servers, routers, switches, and other critical hosts are frequently kept in a locked server room or a remote data center, sometimes hundreds of miles from the technician managing them. SSH is the standard way a technician reaches those devices to configure, update, or troubleshoot them, because everything sent over the connection — including the username and password used to log in — is encrypted. That protects both the administrator's credentials and the commands being run from anyone intercepting the traffic along the way.

SSH replaced an older protocol called Telnet, which sent everything, including passwords, as plain, unencrypted text. Telnet is no longer considered acceptable for managing a production device, and SSH is the expected standard in its place.
